# 能力中心模块 v1.0（草案 · 单开模块）

> 起因：蓝图上「更多 → 更多功能」这一块现在既不是栏目、也不是模块，只是一个把放不下的能力集中塞进去的弹窗。按"那就单开一个模块"落成独立模块：**能力中心**。
> 本文只定模块，不改主流程，也不动三层骨架。

---

## 0. 一句话

主流程之外那些"低频但必须有"的能力，不该藏在第二个「更多」里；给它们一个有名有界的落点——**能力中心**，只负责"找到并打开"，不负责业务动作。

---

## 1. 先回答"这里是哪里"

对照《蓝图全景展开 v1.1》的三层结构：

| 层 | 内容 | 「更多功能」在哪 |
| --- | --- | --- |
| 第一层 骨架 | 材料档案室、完成矩阵、事务时间线 | 不在里面 |
| 第二层 流程 | 收材料 → 审 → 归档 → 催交 → 交差 | 不在里面 |
| 第三层 副驾 | 右栏建议、流程节点建议、命令面板、对话页 | 只在其中一项（AI 助手）有关 |

结论：它挂在三层之外，是**入口层的一块补丁**，蓝图里没有为它定义模块，所以现在没有职责、没有边界、也没有验收口径。

### 1.1 它是"栏目"吗

不是。栏目的本质是"同一维度的标签聚合"，比如台账按材料类别分列、矩阵按人×类别分格，聚合之后每一格都有明确归属和操作。现在这块弹窗里是两组互不相干的能力：

- 智能辅助：AI 助手（进阶）
- 文件与留痕：文件夹收集（本地）、操作日志（留痕）

它们唯一的共同点是"不在主流程里"。这是**收纳**，不是**分类**；所以它看起来像栏目，实际是抽屉。

### 1.2 是在模仿各类吗

是，模仿的是系统级"更多／溢出菜单"（Overflow menu）范式：汉堡菜单放不下的，统一进"更多"。这个范式本身没问题，浏览器、IDE、手机系统都这么干；问题在于本产品把它当成了长期容器——每加一个能力就往下续一层，最后会长成第二套导航，和侧栏打架。

---

## 2. 单开模块的三条理由

1. **职责可命名**：这些能力的共同职责是"低频进阶、必须有、但不进主流程"，可以命名为能力中心，而不是"更多里的东西"。
2. **入口可预期**：用户不必记住"更多里还藏着三个功能"；一级入口一次可达。
3. **边界可守**：模块只做发现与启动，业务动作仍回原页面，避免长出第二套流程。

与既有原则一致：可以弱但不能没有——每个能力保底有一个入口和一句说明，实现可以简化，但不能整块缺失。

---

## 3. 模块定义

| 项 | 定义 |
| --- | --- |
| 名称 | 能力中心（内部代号 hub） |
| 定位 | 低频进阶能力的统一入口与说明页 |
| 入口 | 侧栏一级「能力中心」，位于主流程分组之后（原「更多」位）；原「更多功能」弹窗内容迁入，弹窗废弃 |
| 主页 | 一屏分组卡片 + 本地过滤搜索，无二级页 |
| 职责 | 找到、看懂、打开；附一句边界说明 |
| 不负责 | 提交、审核、归档、催交等任何业务动作 |

实际落地时「更多」分组整组下线，设置固定在侧栏底部（桌面「关于」在设置弹窗内）；不再保留任何第二层能力菜单。

---

## 4. 页面结构（一屏）

```
┌ 能力中心 ─────────────────────────────── 12 项 ┐
│ 页头：标题 + 一句定位 + 搜索（本地过滤）+ 计数     │
├───────────────────────────────────────────────┤
│ 智能辅助                                        │
│  [✦ AI 助手]        本地模型或自有 API，给建议不替你执行  [进阶] │
│  [⚙ 模型与 Key]      选通道、填 Key、看上下文是否出设备      [配置] │
├───────────────────────────────────────────────┤
│ 文件与留痕                                      │
│  [▣ 文件夹收集]      比对目录变化，勾选后登记入账          [本地] │
│  [≡ 操作日志]        提交、审核与导入导出的本机记录        [留痕] │
│  [⤓ 证据包导出]      索引/日志/文件树打成一个 ZIP         [导出] │
│  [↺ 备份与恢复]      导出 JSON，恢复前先看差异预览         [留痕] │
├───────────────────────────────────────────────┤
│ 实验与重活（默认收起）                            │
│  [▤ 本地处理器]      unkernel 起 Linux 跑重活，可选        [实验] │
└───────────────────────────────────────────────┘
页脚：这里只负责找到并打开；具体操作回到对应页面完成。
```

卡片只有四个要素：图标、名称、一句用途、标签；右下角单一主操作（打开／配置）。不放大段说明，不放多个按钮。

---

## 5. 边界（明确不做什么）

1. 不列主流程页面：材料台账、文件室、名单核对、任务跟踪、服务留痕都不进这里。
2. 不做业务动作：不在这里提交、审核、归档、催交。
3. 不复制已有能力：搜索走命令面板，设置走设置页，这里只放"入口 + 一句说明"。
4. 不做隐藏式权限：无权限的卡片置灰并写明原因（如"仅管理员"），不整块消失。
5. 不做第二入口：同一能力不在侧栏、顶栏、能力中心三处同时出现；保留一处主入口，其余用跳转。

---

## 6. 四态

| 态 | 表现 |
| --- | --- |
| 常态 | 分组卡片，计数在页头 |
| 空 / 全未启用 | 顶部保留"主流程三件事"清单与去处理按钮，卡片全灰但可见 |
| 搜索无结果 | 提示"没找到，试试命令面板 ⌘K"，不报错 |
| 权限受限 | 置灰 + 原因标签，点击给出说明 |

---

## 7. 验收尺

1. 从任意页面到任一低频能力 ≤2 次点击。
2. 能力中心内不出现任何主流程按钮。
3. 新增一个能力只需加一张卡，不改导航结构。
4. 关掉 AI 后模块仍可用，AI 卡片显示"未启用"与配置入口。
5. 桌面与网页同一套分组与文案，不出现两套命名。

---

## 8. 实施顺序（顺流而下）

1. 网页先行：侧栏加一级项 → 页面骨架 → 迁移现有三张卡（AI 助手、文件夹收集、操作日志）。
2. 桌面跟进：同一 IA，弹窗改页面，去掉「更多」分组壳，保留原有快捷键。
3. 补两张已有能力卡：证据包导出、备份与恢复（入口已存在，只做跳转）。
4. 权限置灰、四态与空态文案。
5. 最后才考虑"实验与重活"分组，默认收起。

排在 v1.1，不进 v1.0 静默版收口范围。

---

## 9. 待拍板的一件事

入口放哪：

- **A 侧栏一级「能力中心」**（推荐）：与现有分组并列，位置稳定，桌面网页一致；代价是侧栏多一行。
- **B 顶栏工具图标**：省侧栏空间，但和 AI 副驾、提醒、设置挤在一起，低频入口反而更难点到。

按 A 推进；若嫌侧栏变长，可把「更多」整组并进能力中心页脚。
