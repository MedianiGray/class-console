# 办公工作台蓝图 v1.0

> **定义**：工作台是一套统一底座、一组可组合能力、一个能接住任何办公需求的入口；它把「找得到、做得成、交得出、留得下」收在一处。
>
> **目标**：任何一件办公事，都能在这里开始，知道下一步在哪，做完知道放在哪。

## 1. 设计前提

1. **办公需求是不确定的**，不能按功能模块建导航，否则每来一个新需求就多一个孤岛。
2. **办公的共性是「事项」而不是「文件类型」**：材料、会议、通知、报表，本质都是有目标、有对象、有截止、有产出、有留痕的一件事。
3. **协助不是代劳**：系统承担记忆、检索、搬运、校验、重复动作；判断权留给人。
4. **本地优先**：数据在本机，离线可用，可导出、可交接、可销毁。

## 2. 四层架构

```
┌ 入口层 ──────────────────────────────────────────────┐
│ 收件箱 · 场景卡 · 命令面板 · 拖入文件 · 自动化队列    │
├ 剧本层（场景包）────────────────────────────────────┤
│ 材料收审 · 会议活动 · 通知统计 · 报表交差 · 档案整理 │
│ 每个包定义：对象、状态、表单、视图、规则、产出、角色  │
├ 能力层（原子动作）──────────────────────────────────┤
│ 收 · 识 · 整 · 转 · 算 · 查 · 写 · 发 · 排 · 审 · 存 · 交 │
├ 底座层 ──────────────────────────────────────────────┤
│ 对象模型 · 文件库 · 索引 · 权限 · 日志 · 版本 · 备份 │
└──────────────────────────────────────────────────────┘
```

关键判断：
- **能力层共享**：同一个「归档」能力，材料、会议、报表都用，不各写一套。
- **剧本层可配置**：新增一类办公需求，优先加「场景包」，不重做界面。
- **入口层统一**：用户不需要知道能力在哪，只需要说清要办什么事。

## 3. 统一对象模型

工作台不按功能存数据，按**事项**存。

```
Workspace 工作区（班级 / 团队）
└ Scenario 场景（材料收审 / 会议 / 通知 / 报表 / 档案 / 交接）
  └ WorkItem 事项（一次具体的活）
    ├ Object 对象（文件 / 文档 / 表格 / 人 / 日程 / 消息）
    ├ Artifact 产出（归档包 / 报表 / 通知稿 / 证据包）
    └ Record 留痕（状态变化 / 操作 / 备注 / 时间线）
```

一个事项的最小字段：

```json
{
  "id": "wi_20261122_001",
  "scenario": "material",
  "title": "2026 秋季助学金材料收审",
  "state": "collecting",
  "owner": "覃祖悦",
  "due": "2026-11-30",
  "objects": [
    {"type": "file", "path": "收件/助学金/250201_覃祖悦.pdf"},
    {"type": "person", "sid": "250201"}
  ],
  "fields": {"category": "奖助材料", "term": "2026秋"},
  "outputs": [],
  "created_at": "...",
  "updated_at": "...",
  "history": []
}
```

四个「同一」是工作台的底座承诺：**同一套搜索、同一套权限、同一套日志、同一套撤销**。没有这四条，能力再多也是工具箱。

## 4. 界面：一屏五区

```
┌ 顶栏 56 ─────────────────────────────────────────────┐
│ 工作区 ▾    ⌘K 搜索 / 命令        收件 3  身份 ▾  ⚙  │
├ 侧栏 64/212 ┬──── 主工作区 ──────────────┬ 上下文 320 ┤
│ 今日         │ 页头：场景 + 状态 + 视图     │ 事项详情   │
│ 收件箱 3     │                             │ 对象预览   │
│ 事项         │ 列表 / 看板 / 日历 / 文件    │ 产出 / 留痕 │
│ 资产         │                             │ 动作区     │
│ 自动化       │                             │            │
├──────────────┴─────────────────────────────┴───────────┤
│ 状态栏：本地 · 索引一致 · 后台任务 1 · 快捷键          │
└────────────────────────────────────────────────────────┘
```

导航按**工作阶段**分，不按文件类型分：
- **今日**：待我处理、临期、未交、异常。
- **收件箱**：所有新进来的东西，等分流。
- **事项**：进行中的活，按场景与状态筛。
- **资产**：文件、文档、表格、归档索引。
- **自动化**：规则、队列、运行记录。

主工作区四种视图，由场景决定默认：
- 列表（台账 / 清单）
- 看板（按状态分列）
- 日历（截止 / 会议）
- 文件（目录树 + 预览）

## 5. 办公需求地图

| 需求类 | 典型场景 | 工作台怎么协助 | 产出 | 归位 |
| --- | --- | --- | --- | --- |
| 文档 | 起草通知、套模板、改格式 | 模板 + 字段填充 + 版本 | 文档 | 资产 / 归档 |
| 表格 | 汇总、清洗、核对、统计 | 导入 + 规则校验 + 计算 | 表格 / CSV | 资产 / 报表 |
| 演示 | 汇报、答辩、周会 | 提纲模板 + 素材索引 + 导出 | 幻灯片 | 资产 |
| 文件 | 收集、命名、归类、去重 | 扫描 + 识别 + 规则归位 | 归档目录 | 文件库 |
| 信息 | 提取学号、日期、金额 | 文件名解析 + 文本提取 | 结构化字段 | 事项 |
| 沟通 | 通知、催交、回执 | 名单 + 话术模板 + 回执登记 | 通知稿 / 清单 | 日志 |
| 日程 | 截止、会议、周期任务 | 事项截止 + 日历 + 提醒 | 日程 / 任务 | 事项 |
| 流程 | 提交、审核、驳回、归档 | 状态机 + 权限 + 留痕 | 状态记录 | 时间线 |
| 归档 | 材料落盘、索引、检索 | 规则归位 + 索引 + 校验 | 归档文件 | 文件库 |
| 报表 | 周报、月报、评比汇总 | 数据源 + 模板 + 计算 | 报表 / 证据包 | 资产 |
| 会议 | 议题、参会、纪要、待办 | 会议包 + 材料 + 任务 | 纪要 / 待办 | 事项 |
| 交接 | 换届、离职、学期末 | 届别档案包 + 导入 | 交接包 | 归档 |

这张表的用法：**任何新需求先归到一类，再看它需要哪些能力、产出归哪**；不急着加按钮。

## 6. 能力层：十二个原子动作

| 能力 | 输入 | 输出 | 可逆 |
| --- | --- | --- | --- |
| 收 Ingest | 文件 / 表单 / 导入 | 对象 | 是（移入收件箱） |
| 识 Extract | 文件名 / PDF / DOCX | 字段 + 置信度 | 是 |
| 整 Organize | 文件集 + 规则 | 目标路径 | 是（journal） |
| 转 Convert | 文档 / 表格 | 新格式 | 是 |
| 算 Compute | 表格 / 字段 | 统计 / 校验结果 | 是 |
| 查 Retrieve | 关键词 / 条件 | 对象列表 | 只读 |
| 写 Draft | 模板 + 数据 | 文档 / 通知稿 | 是 |
| 发 Prepare | 名单 + 话术 | 可粘贴文本 / 回执入口 | 是 |
| 排 Schedule | 事项 + 截止 | 日程 / 提醒 | 是 |
| 审 Review | 对象 + 规则 | 通过 / 退回 / 异常 | 是（留痕） |
| 存 Archive | 对象 + 规则 | 归档文件 + 索引 | 是（撤销） |
| 交 Handover | 工作区 | 交接包 / 证据包 | 是 |

能力注册表要写清：输入、输出、权限点、是否可逆、失败怎么退。**没有可逆路径的能力，不允许进 L3 自动执行。**

## 7. 场景包机制

一个场景包 = 一套配置，不是一套新代码：

```json
{
  "id": "material",
  "name": "材料收审归档",
  "states": ["收件", "待审", "待补", "已归档", "已驳回"],
  "entry_form": ["category", "title", "owner", "sid", "files"],
  "views": ["list", "file"],
  "capabilities": ["ingest", "extract", "review", "archive", "export"],
  "rules": ["naming", "folder", "index"],
  "outputs": ["archive_index", "evidence_pack"],
  "roles": ["operator", "reviewer", "owner"]
}
```

首批六个包：
1. **材料收审归档**（现有 class-console 的垂直能力，作为第一个包）
2. **会议与活动**（议题、参会、材料、纪要、待办）
3. **通知与统计**（名单、话术、回执、汇总）
4. **档案整理**（扫描、命名、去重、索引、检索）
5. **报表与交差**（数据源、模板、证据包）
6. **换届交接**（打包、导入、权限转移）

新包接入的验收：**不改主界面，只加配置与少量适配代码，就能跑通「收件 → 处理 → 产出 → 归位」。**

## 8. 自动化：助手，不是黑箱

四级权限：
- **L0 观察**：只扫描、只报告。
- **L1 建议**：给识别结果与目标，等人确认（默认）。
- **L2 一键**：dry-run 预览后整批执行，可撤销。
- **L3 规则**：满足条件自动执行，逐条留日志，可回滚，需逐条开启。

统一约束：不删原件、不覆盖同名、不猜没把握的字段、不出工作区根目录。
每个自动化动作都要回答三个问题：**为什么这么做、做了什么、怎么撤回。**

## 9. 数据与可靠性

- **存储**：SQLite 存对象与关系，文件存原目录/归档目录；索引可重建。
- **事务**：批量操作先 preflight，再执行，再校验，最后写 journal。
- **撤销**：每批操作一条 journal，记录源、目标、哈希、动作；支持整批回滚。
- **备份**：启动滚动备份 5 份 + 手动导出；恢复前预览影响范围。
- **完整性**：台账 ↔ 索引 ↔ 磁盘三方比对，给出可修复项。
- **可携带**：工作区可整体导出/导入；换届只带公共记忆，不带个人隐私。

## 10. 权限与角色

角色由场景定义，权限点统一：
- **Owner**：工作区所有者，管场景、权限、交接。
- **Operator**：经办，收件、整理、归档。
- **Reviewer**：审核，通过/驳回/退回。
- **Participant**：提交、查看自己的事项。
- **Guest**：只读或仅提交。

权限点：`read / create / edit / review / archive / export / manage`。
原则：**默认最小权限；导出与删除永远需要明确授权。**

## 11. 视觉与交互系统

- **三层表面**：窗口底 / 卡片 / 抬升面；层级靠表面差与留白，不靠阴影。
- **字阶**：21 页标题 / 13 区块 / 11 正文 / 9 辅助；表头 9 加粗降色。
- **间距**：4 的倍数；页边 24、卡片间 16、卡片内 14。
- **颜色**：十套强调色；状态只用绿/琥珀/红，底色 8% 透明，不整行染色。
- **圆角**：卡片 10、输入 6、标签 4。
- **动效**：140–180ms ease-out，只做淡入与位移。
- **一条主动作**：每个视图只有一个实心按钮，其余 Ghost / 文字链。
- **不用弹窗链**：详情、预览、备注、批量确认都在右栏或底部条。
- **键盘**：`Ctrl+K` 搜索/命令，`↑↓` 选行，`Enter` 打开，`Space` 预览，`Esc` 收右栏。

## 12. 路线图

### W1 底座版
- 对象模型、收件箱、统一搜索、右栏详情、归档与索引、操作日志、撤销 journal、草稿自动保存。
- 验收：任意文件能进收件箱、被描述、被找到、被归档、能撤回；杀进程重开草稿还在。

### W2 场景版
- 场景包引擎；先落「材料收审」与「会议活动」两个包；列表/看板/文件三视图；表单与状态机配置化。
- 验收：新增一个场景包不改主界面；两个包共享同一套搜索、权限、日志、归档。

### W3 自动化版
- 规则引擎、试运行、待确认队列、文件夹监听、哈希去重、命名模板、批量重命名、索引校验。
- 验收：20 个文件批量整理一次完成；撤销后回到操作前；零原件丢失。

### W4 交差与交接版
- 完成矩阵、催交话术与回执、周报月报、证据包、届别交接包、恢复预览。
- 验收：证据包脱离软件可读；交接后新环境十分钟可继续工作。

### W5 静默版
- 首次引导、空态/错误态、性能、无障碍、安装与升级说明。
- 验收：新用户 3 分钟完成第一件事；10k 对象搜索 ≤100ms；冷启动 ≤1s。

## 13. 不做与反模式

**不做**：云同步、账号与多人实时协作、插件市场、生成式 AI 代写代判、独立聊天、移动原生、多租户。

**反模式**：
- 功能宫格：把工作台做成应用启动器。
- 仪表盘化：只有数字，没有下一步动作。
- 一功能一存储：搜索、权限、日志各一套。
- 弹窗链：每步都打断。
- 自动化黑箱：不解释、不可撤销。
- 用“所有需求”当借口堆按钮。

## 14. 成功标准

1. 任何办公需求能在**一个入口**开始，≤3 步进入执行。
2. 单件事的上下文切换 ≤1 次。
3. 任意对象/文件/人，≤2 个动作找到。
4. 零原件丢失，撤销成功率 100%。
5. 新增场景包 ≤1 天配置接入，不重做界面。
6. 关掉重开，未完成的事仍在原地。

## 附：与现有产品的关系

`class-console` 是这套工作台的**第一个垂直场景包**，不是全部。
它的价值在于验证了「本地优先 + 材料收审归档 + 索引留痕」这条链路；下一步不是把它做得更大，而是把它的底座抽出来，让第二个场景包（会议/通知）复用同一套对象、搜索、权限、日志与自动化。
