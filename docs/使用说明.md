# 工作台使用说明

> 面向班级学委、辅导员老师的操作手册。照着本说明即可完成材料收集、审核核对、留痕与备份。
> 本工具是**离线本机工具**：数据保存在自己这台电脑上，断网可用；不需要注册账号，也不把材料传到网上。

## 一、这是什么

班级材料操作台，把一份材料从"交上来 → 审核 → 归档 / 驳回 → 留痕"的过程收拢在一个窗口里完成。提供两种形态，功能一致、数据各自独立：

- **桌面版（Windows exe）**：双击独立运行，数据存在本机 SQLite 数据库。
- **网页版（单文件 HTML）**：用浏览器打开，数据存在浏览器本地缓存（localStorage），可挂在 GitHub Pages 上做预览。

> 两端数据互不同步：桌面版里录入的材料不会出现在网页版，反之亦然。需要迁移时用各自的备份功能导出导入。

## 二、界面布局

左侧为导航栏，右侧为当前视图；左下角可切换岗位视角（经办人 / 审核者 / 汇总者 / 申请人），当前身份在底部状态栏留痕；底部状态栏同时显示本地模式与条数，操作后会有临时提示。

侧栏按「办理材料 / 跟进核对」分组，末位是独立的「能力中心」。两端都把它做成一页分组卡片：智能辅助（AI 助手 / AI 建议）、文件与留痕（文件夹收集、操作日志，网页另有备份与恢复，桌面另有证据包）；按岗位显隐，点卡片才跳转，操作仍回原页面。页内可搜索，折叠侧栏后能力中心只留「◇」。

| 驳回 | 可 | 可 | 可 | — |
| 导出 CSV | 可 | 可 | 可 | — |

| 文件夹收集 | 可 | 可 | 可 | — |
| 名单添加 / 移除 / 清空 | 可 | 可 | 可 | — |

### 2.1 首次上手

第一次打开，概览顶部会出现一张「三步上手」卡，不弹欢迎弹窗。通用岗位按三步走：

1. **录入或收集第一份材料**：手动提交，或从文件夹收集登记；
2. **审核并归档**：通过后写入归档目录，留下第一条操作记录；
3. **核对名单 / 登记任务**：知道谁没交、什么时候截止。

前两步完成后，卡片会自动收起，并提示「上手完成」。之后网页从「能力中心 → 使用帮助」、桌面从「设置 → 使用帮助」还能重看；网页版的状态栏会显示「含示例数据」，示例数据不计入上手进度，也可以在卡片上直接清空。

申请人视角只显示「填写学号 → 提交材料 → 查看进度」，不会出现审核与名单步骤。

桌面版把「使用帮助」放在设置弹窗底部；从帮助里可以「重新显示在概览」。

## 三、各视图操作

### 3.1 工作台概览

- 材料四态卡片（总数、待审核、已归档、已驳回）全员可见；未交材料卡需名单维护权，临期 / 逾期任务卡需任务管理权，无对应权限的岗位不显示。
- 中部显示各类别材料数量分布；右栏按权限让位：有日志查看权显示近期动态，无日志权但有名单权时显示未交材料清单（点击直达名单视图），两者皆无则右栏留空。
- 待办队列按岗位拆分：申请人看「需我关注的材料」（待审核 + 已驳回），审核者 / 汇总者看「待审核 · 需处理」，经办人看「待审核 · 跟进」；点击条目可跳到台账。
- 台账默认筛选：审核者 / 汇总者默认「待审核」，其余岗位默认「全部」；在台账内手动改的筛选不会因切换岗位被覆盖。

### 3.2 材料台账

- **搜索**：在顶部输入材料名、姓名或学号，实时过滤。
- **筛选**：按类别（团务 / 奖助 / 学分 / 宣传 / 班级事务）、按状态（待审核 / 已归档 / 已驳回）筛选。
- **查看**：选中一条，双击或按回车，或点"查看"，弹出详情；详情内附该材料最近的操作记录。
- **归档 / 驳回**：按岗位权限点显示（归档：审核者 / 汇总者；驳回：经办人 / 审核者 / 汇总者）。选中材料后点"归档"或"驳回"，在弹出的备注框里可填写说明（可选，驳回建议写明原因），确定后状态更新并自动写入日志。
- **导出 CSV**：把当前筛选出来的记录导出为 CSV 文件，可用 Excel 打开。

### 3.3 名单核对

- 顶部统计应交、已交、未交人数。
- **添加成员**：填写学号（纯数字）与姓名保存；学号重复或格式不对会被提示。
- **移除选中**：从名单中删掉一名成员。
- 核对口径：名单内学号在材料记录中出现过即视为“已交”；材料里有学号但名单中没有，记为游离材料，便于发现录错学号。
- **完成矩阵（服务操作条）**：切到“完成矩阵”标签，选中一名学生并指定类别，底部会显示“姓名 · 学号 · 类别：状态”。
  - **免交 / 延期**：登记原因必填；延期还要填未来截止日，到期后自动变“已到期”。同一学生同一类别只保留最新一条登记，可再次打开取消。
  - **生成催交**：只对“补交 / 无记录 / 回执·稍后”生成话术；待审、免交、延期不催。话术可复制，登记后同一学生 24 小时内不能再次催交。
  - **登记回执**：同学说已交、已在校外提交或稍后补时登记；回执不改材料状态，只停止追赶并留痕。回执后矩阵显示“回执·已交 / 回执·校外 / 回执·稍后”。

### 3.4 服务留痕

- 顶部四张卡：近 7 天催交、近 7 天回执、有效免交、有效延期。
- 支持关键词搜索与类型筛选；表格列出时间、类型、学生、学号、类别、内容与渠道。
- 选中一条，底部显示完整催交话术或备注，可一键复制。
- **导出 CSV**：把当前筛选结果导出，UTF-8-SIG 编码，Excel 直接打开。

### 3.5 任务跟踪

- 顶部统计进行中、临期（截止日 ≤2 天）、逾期、已完成数量。
- **添加任务**：填写标题、关联类别、截止日期（格式 YYYY-MM-DD）、应交范围、备注。
- **编辑**：选中任务后修改内容。
- **完成 / 还原**：切换任务是否已完成。
- **删除**：删除选中任务（需确认）。

### 3.6 提交材料

1. 填写材料名称、姓名、学号、材料类别；说明和附件为可选。
2. 学号须为纯数字；必填项留空或学号格式不对时，表单下方会就地提示，材料不会入库。
3. 如与已有记录学号、材料名、类别重复，会提示确认是否再次提交。
4. 点"提交材料"，新材料进入台账，状态为"待审核"，日志新增一条"提交"。
5. "清空"会撤销当前已填内容，已填写时需确认。

### 3.7 操作日志

- 记录每条操作的时间、操作人、角色、动作、对象和来源。
- 顶部可按关键词、动作和操作人筛选，右侧显示"匹配 x / 共 y 条"；"清空"恢复全部。
- **导出证据包**：按类别、提交日期导出 ZIP，内含材料清单、归档索引、操作日志、文件树和说明，可选附带归档原文件；评审方不装软件也能核对。
- **导出备份**：把材料、日志、名单、任务、模板字段和流转事件打包为 JSON 文件保存。
- **导入备份**：选择此前导出的 JSON 文件；先显示当前与备份的数量、重复编号、缺事件等预览，确认后才覆盖，结构不正确或失败时回滚不写入。

### 3.8 完整性检查

- 入口在"设置 → 材料归档 → 完整性检查"。
- 对话框会把索引、磁盘与台账三方比对，分类列出归档文件缺失、已归档无路径、源文件缺失、索引缺记录、索引路径不一致、索引孤儿和磁盘未登记文件。
- **重建索引**：按当前台账重写 `_归档索引.csv`，不改材料文件。
- **重新归位缺失文件**：只处理"已归档但归档文件缺失、源文件仍在本机"的材料，重新复制到归档目录并补一条"归位"事件。
- 两类修复都要二次确认，且不会删除归档目录里的任何文件；磁盘上多出的文件只报告，需人工判断。

### 3.9 文件室（桌面版）

- 左侧归档目录树、中间文件列表、右侧预览。顶部可搜索整个归档根的文件名，面包屑可回上一级。
- 文件列表按台账与索引标出「台账有 / 仅索引 / 未登记」，并显示编号；窗口变窄时先保文件名与登记状态。
- 选中文件后：文本看前 200 字，图片与 PDF 看资源管理器同款首页缩略图，其他类型可从系统打开；底部可「在资源管理器打开」，台账有的可「去台账」。
- **缺失文件**：点顶部「缺失文件 N」查看缺档清单，双击回台账找责任人；源文件仍在本机时可「重新归位」。
- **拖入登记**：把文件直接拖进窗口。当前目录已能看出类别与学生时，会复制到归档目录并登记为待审核（同名自动加 `_v2` / `_v3`，不覆盖）；目录信息不全时才弹登记框补类别、姓名与学号。
- 登记只复制、不移动原文件；登记后会刷新台账、索引与文件室，并写一条「文件室登记」日志。

## 四、一次材料收集的完整流程

1. **提前建名单**：到"名单核对"把本班学号—姓名录入。
2. **登记任务**：到"任务跟踪"建一条收集任务，写清截止日期和应交范围。
3. **申请人 / 经办人提交**：在"提交材料"录入，或由经办人把收齐的材料逐条登记进台账。
4. **审核**：审核者 / 汇总者在台账查看详情，合格的归档，不合格的驳回并注明原因。归档后可到「文件室」核对文件是否落到正确目录，缺失的会列在「缺失文件」里。
5. **跟进**：回到"名单核对"切到完成矩阵，对未交的同学生成催交话术；确实免交或延期的先登记，同学回复已交 / 校外提交 / 稍后补时登记回执，避免反复打扰。
6. **复盘**：到「服务留痕」看近 7 天催交与回执、有效免交与延期，确认哪些人还需要继续跟进。
7. **核对文件**：到「文件室」按目录树逐层看归档文件，顶部「缺失文件」清零；确有缺档的，用「重新归位」或拖入补登记。
8. **收尾**：在任务跟踪把已完成的任务标记完成；导出一份 JSON 备份留存；换届时再导出一份交接包。

## 五、备份与恢复

- **备份**：操作日志视图 → "导出备份"，选择保存位置，得到一个 `.json` 文件。请在学期中段和收尾时各导出一份，妥善保存。
- **恢复**：换电脑或误操作后，在操作日志视图 → "导入备份"选择该 JSON 文件，确认后材料、日志、名单、任务一并恢复。
- 备份文件是纯文本 JSON，可用文本编辑器查看内容；其中包含学号、姓名等信息，请按敏感材料保管。

### 届别交接包

- 入口在"设置 → 数据"卡片：**导出交接包** 生成 ZIP，内含数据备份、交接说明、manifest；存在归档索引与设置时一并放入。
- 交接包只带索引与登记，**不含原始材料文件**；新任学委拿到包后仍需接管原归档目录，才能打开历史附件。
- **导入交接包** 会先显示包摘要与覆盖预览，确认后才恢复；包里的设置仅作参照，不会自动覆盖新电脑的设置。
- 适合学期末或换届时交接；日常留档仍建议使用 JSON 备份。

## 六、数据存放位置与隐私

- **桌面版**：数据目录在 Windows 的 `%APPDATA%\ClassConsole\`
  - `console.db`：材料、日志、名单、任务数据库。
  - `crash.log`：未捕获异常的错误日志。
  - `console.corrupt-*.db`：数据库损坏时隔离保留的旧文件。
- **网页版**：数据保存在当前浏览器的本地缓存；清理浏览器站点数据会清除网页版记录，清理前先导出备份。
- 程序默认不主动联网；不收集、不上传个人信息。学号、姓名等仅用于本机台账与核对。

## 七、常见问题

**换电脑后历史附件打不开？**
当前版本附件只记录文件名，文件本身没有落盘保存。需要在换电脑前把原始文件一并带走。附件真实落盘属于待做能力（见《能力范围评判.md》B 类）。

**材料丢了 / 误删怎么办？**
如果此前导出过 JSON 备份，用"导入备份"恢复；没有备份的本地记录无法找回。建议定期备份。

**网页版和桌面版记录对不上？**
两端存储相互独立，不互通。确认自己在哪一端录入，到对应端查看。

**为什么看不到归档 / 驳回、导入、名单维护、任务增删或备份导入按钮？**
当前岗位视角没有对应权限点，这些入口按岗位裁剪显示；在左下角切换到具备该权限的岗位即可。该视角切换是演示性质，未接账号密码登录，也不是服务端强制权限。

**导入备份提示结构不正确？**
所选文件不是本工具导出的备份，或文件已损坏。请重新选择此前导出的 `.json` 备份。

## 八、能力边界（务必知悉）

- 本工具是单机离线台账，**没有**账号登录、多人协作、跨设备同步、云端附件和在线提交功能。
- 岗位切换只做界面层裁剪，不做服务端真实权限校验，也无记录级数据范围隔离，不能作为防越权依据。
- 尚未在不同 Windows 版本、分辨率、字体缩放和大批量数据下做过长时实测。
- 哪些能做、哪些需要后端、哪些属于规划关闭项，完整对照见《能力范围评判.md》。
