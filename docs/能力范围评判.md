# 能力范围评判

> 用途：在动手或选型前，先把"这套操作台现在能做什么、做不了什么、哪些需要后端、哪些只是默认关闭"讲清楚，避免把纯静态离线工具当成需要账号、协作、云端的系统来期待。
> 定位基线：**纯静态、离线优先、本机存储**。桌面版走本机 SQLite，网页版走浏览器 localStorage，两者都不起后端服务、不接账号体系、不做多人协作。
> 当前版本：v0.2.2 迭代线（本地打磨版）。

## 一、评判口径

- **本机闭环**：不联网、不写服务端，单机即可完成录入、审核、核对、留痕、备份。
- **静态边界内可做**：仍可在本地程序或纯静态网页内实现，不需要服务器、数据库服务端或公网写入通道。
- **必须后端才能做**：缺少服务端、数据库、鉴权或公网接收写入的通道就无法成立，本版不承诺。
- **规划默认关闭**：技术上可行但当前不启用，做成可插拔连接器，由用户主动开启并确认数据流向。
- **待评估深化**：需求形态尚未锁定，先记录不排期，确有需要再细化。

## 二、A. 已具备能力（本机离线闭环，已回归通过）

| 模块 | 已具备的能力 | 桌面版 | 网页版 |
|---|---|---|---|
| 工作台看板 | 材料总数 / 待审核 / 已归档 / 已驳回卡片、类别分布、待办置顶、近期动态；未交人数、临期/逾期任务摘要直达对应视图 | 有 | 有 |
| 材料台账 | 按材料名 / 姓名 / 学号搜索，类别与状态筛选，查看详情，单条材料留痕时间线 | 有 | 有 |
| 提交材料 | 名称 / 类别 / 姓名 / 学号必填校验，学号纯数字格式校验，重复提交确认，附件名记录，说明与草稿 | 有 | 有 |
| 审核流转 | 归档、驳回，可填写备注或原因并随材料留存，详情可见；同学视角隐藏审核与管理类入口（归档/驳回、CSV 导入、名单维护、任务增删改、备份导入）；未选中时按钮禁用 | 有 | 有 |
| 名单核对 | 学号—姓名名单存本机，核对应交 / 已交 / 未交与游离材料；增删成员 | 有 | 有 |
| 任务跟踪 | 待办台账，关联类别、截止日期、应交范围、备注；自动标记临期（≤2 天）/ 逾期；完成切换、编辑、删除 | 有 | 有 |
| 导入导出 | 台账当前视图导出 CSV（带 BOM，Excel 可直接打开）；JSON 备份恢复携带材料、日志、名单、任务 | CSV 导出；JSON 备份 | CSV 导出；CSV 批量导入；JSON 备份 |
| 操作日志 | 时间 / 操作人 / 角色 / 动作 / 对象 / 来源自动留痕，可追溯 | 有 | 有 |
| 健壮性 | 字段兜底、脏数据跳过、通配符字面匹配、写操作异常转提示、异常落盘、坏库隔离重建、旧库自动迁移补列 | 有 | 有 |

> 回归基线：数据层自检 18 项、GUI 冒烟、网页 Node 冒烟在本机通过；浏览器在线版六视图走查控制台无报错。

## 三、B. 静态 / 离线边界内可做，本轮未做

这些不依赖后端，后续在本地程序或纯静态网页内即可实现，属于"本地打磨"范畴：

| 事项 | 说明 | 现状 |
|---|---|---|
| 附件真实落盘 | 把提交的文件复制到本机材料目录，台账可直接定位、打开；当前仅记录文件名 | 未做 |
| Excel（.xlsx）解析导入 | 读取原生 Excel 表格批量入库；当前 CSV 已通，xlsx 解析未做 | 未做 |
| 名单批量粘贴导入 | 从剪贴板或文本批量粘贴学号—姓名入库；桌面侧尚未提供 | 网页侧可逐条添加 |
| 学号—姓名强一致性校验 | 提交时对照名单校验学号与姓名是否匹配，给出强提示 | 网页侧有一致性提示，桌面侧待对齐 |
| 文件名规范检查 | 对附件命名、材料命名做规范提示 | 未做 |
| 桌面侧表格偏好对齐 | 排序、列显隐、列宽、密度等偏好本机记忆；网页侧已具备，桌面侧待对齐 | 部分 |
| 首次使用引导、程序图标、深色模式 | 体验细节增强 | 未做 |
| 定时本地备份 | 按周期自动导出一份 JSON 备份到指定目录 | 未做 |
| 任务—材料逐条关联 | 把具体任务与逐条材料、逐人提交状态挂钩；当前任务定位为待办与截止提醒 | 未建模 |

## 四、C. 必须后端 / 服务端才能实现（本版边界外，不承诺）

下列能力在纯静态、本机单机形态下无法成立；要实现需要服务端程序、服务端数据库、鉴权体系或公网写入通道：

| 能力 | 为什么静态本机做不到 | 本版现状 |
|---|---|---|
| 账号注册 / 登录、2FA、密码找回 | 需要服务端保存与校验凭据，前端不能安全存密码 | 未实现；角色仅为本地视角切换 |
| 服务端强制分级权限、越权审计 | 权限判定必须在可信服务端执行，前端绕过即可改数据 | 未实现 |
| 多人实时协作、并发编辑、冲突合并 | 需要共享数据库与变更同步机制 | 未实现 |
| 跨设备 / 跨人数据同步 | 需要中转服务端在设备之间搬运数据 | 未实现；桌面 SQLite 与网页 localStorage 各自独立 |
| 云端附件存储、在线收集入口 | 需要服务端接收并保存上传文件；GitHub Pages 纯静态无法接收写入 | 未实现 |
| 主动消息推送（短信 / 群机器人 / 邮件） | 需要服务端定时触发并持有通知渠道凭据 | 未实现 |
| 服务端 AI 能力 | 若把 API 密钥放在前端会泄露；需要后端代理调用、限流与留痕 | 未实现（见 D 类规划） |
| 公网可访问的在线提交 | 静态站点只能展示，不能落地接收同学提交 | 未实现 |

## 五、D. 规划默认关闭项（外部对接，主动启用）

技术上可行，但当前默认关闭；对接层做成通用适配器，地址、凭据、字段映射走配置，不绑定单一平台。启用前需明示数据流向，并保留切回纯本地的开关。

| 编号 | 规划项 | 说明 |
|---|---|---|
| B8 | 本机文件夹收集 | 扫描 / 监听指定文件夹，自动识别材料文件并登记台账 |
| B9 | 平台对接（WPS / 飞书 / 钉钉等） | 先只读同步试点，字段映射确认后再开放写入；接附件存储与通知 |
| B10 | 网页链接数据识别 | 识别提交内容里的链接，抽取标题 / 摘要等信息 |
| B11 | AI 辅助 | 分类建议、齐全度检查、重复识别、文案草稿、检索问答；**AI 只出建议，归档 / 驳回等关键动作由人确认**，AI 结果入日志留痕 |

## 六、E. 待评估深化项（需求未锁定，先不排期）

- **任务与材料逐条人—材料关联**：当前任务是待办与截止提醒，尚未细化到"某任务下谁交了哪份材料"的关联模型。
- **桌面版与网页版数据互导**：两端存储格式不同，目前各自独立；是否需要一套通用交换格式（如统一 JSON 包）待确认。
- **学期归档包 / 审计导出**：按学期汇总材料、日志与名单，打包归档；字段范围与格式待业务方确认。
- **手机端查看形态**：只读查看还是需要轻交互，是否复用现有网页版，待需求明确。

## 七、选型对照结论

| 方案 | 适用场景 | 局限 |
|---|---|---|
| 纯静态本机工作台（本方案） | 学委 / 老师单人或小范围使用，材料台账、审核核对、留痕备份，离线可用、零运维、隐私留在本机 | 无账号、无协作、无同步、无云端收集 |
| 低代码平台 / 多维表格 | 需要快速搭表单、视图与协作，可接受平台账号与平台规则 | 数据在第三方平台，受平台配额、权限与导出限制约束 |
| 完整前后端 + BaaS | 需要账号权限、多人协作、在线提交、云端附件、消息通知 | 要维护服务端、数据库与凭据，成本与运维复杂度高 |
| 自研后端服务 | 对数据归属、等保合规、深度定制有硬性要求 | 开发与运维投入最大，需长期维护 |

**结论**：本操作台定位为**离线单机的材料台账与流程留痕工具**，解决"材料进来 → 状态流转 → 归档留痕 → 备份可恢复"的本地闭环；它不替代需要账号体系、多人协作或云端收集的系统。当业务确实出现多人在线提交、跨设备同步、强制权限等需求时，再按 D / C 类方向评估平台接入或后端方案，并保留切回纯本地的退路。

## 八、边界提示（如实说明）

- 角色切换为演示性质，未接账号登录与真实分级权限，不能据此认为已防越权。
- 附件当前只记录文件名，文件本身未落盘；换电脑后历史附件打不开。
- 自检覆盖代码路径与常见边界，不等于所有环境、所有数据组合零缺陷；尚未在老师本人电脑与大批量数据下实测。
- 桌面版与网页版数据互不同步，备份文件格式不互通。
