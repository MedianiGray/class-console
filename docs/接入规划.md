# 班级操作台 · 后续接入规划（大厂服务 / AI API）

## 一、现状与基础

当前版本是纯本地桌面程序：Tkinter 界面 + 本机 SQLite，离线可用，数据不离开本机。
数据读写已经收敛在 `database.py` 的仓库层，界面只调用统一方法，不直接碰 SQL：

```
list_docs / add_doc / archive_doc / reject_doc
list_logs / add_log / stats / backup / restore
```

这一层就是后续接入云端和 AI 的接缝：新增实现同一组方法的远程仓库即可切换，界面和流程不用重写。

## 二、总体原则

1. **离线优先，联网可选**：断网时本地功能完整可用；联网能力作为增强，失败时回退本地，不卡死、不丢数据。
2. **先本地后云端**：先把单机体验打磨到位，再接平台；不为用不上的协作功能提前复杂化。
3. **可回退、可迁移**：任何云端数据都能导出，不被单一平台锁死；接口层留开关，能切回本地。
4. **隐私最小化**：学号、姓名等个人信息只在必要范围使用；上传和 AI 调用前评估脱敏；敏感材料保留"不出本机"的选项。
5. **AI 只做建议，不替人拍板**：分类、摘要、话术由 AI 草稿，归档、驳回等关键动作仍由人确认。

## 三、阶段一：本地打磨（不联网，优先做）

这些不依赖外部服务，先把单机版做扎实：

- **附件真实落盘**：选择文件后复制到本机材料目录，台账可直接打开、定位文件；不再只记文件名。
- **导入导出**：材料与日志支持导出 Excel / CSV；支持按名单批量核对谁交谁没交。
- **审核备注**：驳回、归档时记录原因，写入材料状态和操作日志。
- **统计看板**：待办数量、各类别分布、近期提交趋势；待审核材料置顶提醒。
- **校验增强**：学号与姓名对应校验、重复提交提示、文件名规范检查。
- **体验细节**：列宽记忆、表头排序、首次使用引导、程序图标、可选深色模式。

## 四、阶段二：接入大厂平台服务（有真实多人需求时再做）

### 4.1 可选平台对比

| 方向 | 代表 | 适合场景 | 注意点 |
|---|---|---|---|
| 协作多维表格 | 飞书多维表格、钉钉宜搭、WPS 多维表格 | 材料台账在线共享、班委协同核对 | 需平台开放 API 和对应账号权限 |
| 收集表单 | 企业微信/钉钉收集表、问卷星 | 同学在线提交材料 | 只收不审，状态流转仍要本系统补 |
| 对象存储 | 阿里云 OSS、腾讯云 COS、七牛云 | 附件文件集中存放、生成访问链接 | 需 bucket、访问密钥和访问控制 |
| 消息通知 | 平台机器人 webhook、短信 | 待审核提醒、催交通知 | 注意频控和打扰程度 |

**选型建议**：先看学校/班级实际在用哪个平台（飞书、钉钉还是 WPS），优先接同一家，减少账号和推广成本；附件存储在平台自带云文档够用时，不单独上对象存储。

### 4.2 对接架构

在仓库层新增 `RemoteRepository`，实现与本地仓库同一组方法，由 `DATA_BACKEND` 开关切换：

```
本地 SQLite（默认）  ←→  远程仓库（平台 API / 对象存储）
```

模块拆分：

- **账号与鉴权**：对接平台 OAuth 或通讯录登录；token 本机安全存储，过期自动刷新；角色映射到管理员 / 班委 / 同学。
- **材料同步**：
  - `list_docs` → 查询平台表格记录；`add_doc` → 新增记录；
  - `archive_doc / reject_doc` → 更新记录状态字段；`list_logs / add_log` → 同步日志表。
- **附件存储**：文件上传到云文档或对象存储，台账保存链接 / 文件 key，不再只存文件名。
- **通知**：待审核、被驳回时通过平台机器人推送提醒。
- **一致性策略**：离线期间的本地变更记入同步队列，联网后推送；冲突以"最后更新时间"为准，关键状态变更保留人工确认。接口失败时先用本地缓存，联网后再补同步。

### 4.3 落地步骤

1. 选定一个试点平台，开通开放能力，拿到应用凭证和测试表格。
2. 先做只读同步（云端台账读进来），确认字段映射无误。
3. 再做写入同步（提交、归档、驳回回写云端），加本地队列和失败重试。
4. 接附件上传与链接回写。
5. 最后接通知提醒；全程保留"切回纯本地"的开关。

## 五、阶段三：接入 AI API（在本地数据和流程稳定后）

### 5.1 场景清单（按价值和风险从低到高排）

1. **材料自动分类建议**：根据名称和说明，建议归入团务 / 奖助 / 学分 / 宣传 / 班级事务，人确认后生效。
2. **材料齐全度检查**：对照该类材料应有项，提示缺什么（如缺复印件、缺签字）。
3. **重复 / 相似材料识别**：提醒同一人重复提交或内容高度相似的材料。
4. **文案草稿生成**：自动生成驳回原因说明、催交通知话术、审核备注草稿。
5. **自然语言检索问答**：例如"谁还没交奖学金材料""本学期归档了哪些宣传材料"，基于本地日志和台账回答。

### 5.2 接入架构

AI 单独成一个 `ai_service` 模块，不混进仓库层：

- 统一封装请求：模型地址、密钥、超时、重试、降级开关集中配置。
- **降级回退**：AI 不可用或未配置时，分类等功能回退到本地规则，不影响主流程。
- **数据边界**：可配置哪些字段允许发给模型；敏感材料可设为不调用 AI；发送前做必要脱敏。
- **结果留痕**：AI 给出的建议记入日志，便于追溯；关键动作仍人工确认。

### 5.3 模型与配置

- 可选国内大模型服务（豆包 / 火山方舟、通义、文心、DeepSeek 等），HTTP 调用，密钥和接口地址写配置文件，支持更换模型。
- 优先用轻量、便宜的模型做分类和摘要；问答类再考虑更强模型。
- 调用频率和费用可控：批量处理而非每条实时调用，结果本地缓存。

### 5.4 落地步骤

1. 先做"分类建议"试点：输入材料名称/说明，输出建议类别，本地可校验对错。
2. 再加齐全度检查和重复识别。
3. 然后做文案草稿；最后做检索问答。
4. 每一步都保留关闭 AI、回退本地规则的选项。

## 六、阶段四：远期方向

- 多人实时协作与手机端查看（依赖云端后端，按实际人数和场景再评估）。
- 学期材料一键打包归档；操作日志导出审计包，供老师查阅追溯。
- 与学校现有系统对接（如有统一身份或档案系统）。

## 七、现有代码衔接点

| 要做的事 | 改动位置 | 说明 |
|---|---|---|
| 切换本地/远程后端 | `database.py` 的 `build_repository` 与 `DATA_BACKEND` | 新增远程仓库实现同契约方法 |
| 平台凭证、模型地址、开关 | 新增 `config.json` 配置文件 | 不写死在代码里，便于修改 |
| 网络请求层 | 新增 `cloud_client.py` | 标准库 urllib 起步，需要时再引 requests |
| AI 调用 | 新增 `ai_service.py` | 与仓库层解耦，支持降级 |
| 界面设置项 | 主窗口新增"设置 / 同步 / AI"入口 | 状态指示：本地 / 已同步 / 离线 |

## 八、风险与合规

- **个人信息**：学号、姓名最小化收集；传输加密；云端按角色控制可见范围。
- **平台依赖**：接口配额、费用、政策变化要有预案；数据可导出，避免锁定。
- **AI 可靠性**：模型可能误判，输出仅作建议；敏感材料归档必须人工复核。
- **离线可用**：任何云端或 AI 故障都不能阻断本地提交、归档和查看。

## 九、建议优先级

1. 先完成阶段一的本地打磨（附件落盘、导入导出、备注、看板）。
2. 阶段二先选学校在用的一个平台做只读同步试点，再逐步开放写入。
3. 阶段三从"分类建议"切入，验证 AI 准确率后再扩场景。
4. 多人实时协作、手机端放到最后，确有需求再投入。
