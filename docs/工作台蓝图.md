# 班级材料操作台 · 工作台蓝图

> 目标态与最新根本以《办公工作台蓝图-v2.0.md》为准；本篇保留早期定位、模块与本地实现细节。

> 总纲视图：这份文档说清"做什么、为谁做、现在有什么、怎么分层、往哪走"。
> 外部服务接入细节见《接入规划.md》；可选能力开关策略与通用对接架构见《可选能力与通用对接蓝图.md》；版本规则与稳定性措施见《迭代与稳定性方案.md》。
> 当前版本：v0.2.0（本地打磨版），纯本地桌面程序。

## 一、项目定位

一句话目标：给班级学委 / 辅导员老师一个**离线可用、数据留在本机**的材料工作台，把材料从提交、审核、归档到留痕的流程收拢在一个程序里闭环。

- 交付形态：Windows 桌面 exe，双击即用，不要求安装 Python，不起本地服务、不开浏览器。
- 数据归属：材料与日志保存在本机应用数据目录，断网可用；桌面端不提前启用联网与 AI，网页版另有可选的本地模型 / 自填 API 通道。
- 与早期导航页的区别：导航页只跳转外链；本系统要管"材料进来 → 状态流转 → 归档留痕"的业务过程。

## 二、要解决的问题

| 没有它时 | 有它之后 |
|---|---|
| 材料散落在聊天、云盘、邮箱，靠翻记录找 | 统一台账，按类别、姓名、材料名、状态检索 |
| 谁交了、谁没交、材料是否合格说不清 | 待审核 / 已归档 / 已驳回状态清晰，可按状态筛选 |
| 经手过程靠记忆，事后说不清谁处理过 | 每次提交、归档、驳回、查看自动记入日志，可追溯、可导出 |
| 换电脑或误操作后材料找不回 | 本机 SQLite 存储，支持导出备份与导入恢复 |

## 三、用户与角色

| 角色 | 界面称呼 | 职责 | 当前权限 |
|---|---|---|---|
| 管理员（学委 / 老师） | 管理员 | 查看台账、归档、驳回、查看日志、备份恢复 | 全部操作 |
| 同学 | 同学 | 提交材料、查看本人相关信息 | 仅提交，不出现归档 / 驳回入口 |

> 说明：当前视角切换为演示性质，尚未接入账号密码登录与分级权限；真正按身份限权属于后续阶段。

- 阶段二：接入学校在用平台（飞书 / 钉钉 / WPS 等），在线收集、协同、附件云存、消息通知；外部对接能力默认关闭，经用户确认后启用，对接层做成通用适配器。

## 五、分层架构

```
┌─────────────────────────────────────────────┐
│ 界面层  ui_main / ui_docs / ui_submit / ui_logs │
│ 侧边导航、三视图堆叠、角色切换、状态栏反馈      │
├─────────────────────────────────────────────┤
│ 仓库层  database.py · LocalRepository          │
│ 统一方法契约，界面不直接碰 SQL；异常转 RepositoryError │
├─────────────────────────────────────────────┤
│ 数据层  本机 SQLite（console.db）               │
│ 种子数据 seed.py；损坏隔离重建；JSON 备份恢复    │
└─────────────────────────────────────────────┘
```

**可替换接缝**：仓库方法契约固定如下，将来新增 `RemoteRepository` 实现同一组方法，由 `DATA_BACKEND` 开关切换，界面与业务流程不用重写：

```
list_docs / add_doc / archive_doc / reject_doc
list_logs / add_log / stats / backup / restore
```

## 六、数据模型

### 6.1 材料表 `docs`

| 字段 | 含义 |
|---|---|
| id | 自增主键 |
| name | 材料名称 |
| cat | 类别：团务材料 / 奖助材料 / 学分材料 / 宣传材料 / 班级事务 |
| who | 提交人姓名 |
| sid | 学号 |
| note | 说明 |
| file | 附件名（当前未落盘） |
| time | 提交时间（月-日 时:分） |
| status | 状态：待审核 / 已归档 / 已驳回 |
| scope | 可见范围，默认全员 |

> 预留状态"待补材料"已在界面筛选枚举中，数据层暂未单独产生该状态，后续审核备注流程落地时启用。

### 6.2 日志表 `logs`

| 字段 | 含义 |
|---|---|
| id | 自增主键 |
| time | 操作时间 |
| who | 操作人 |
| role | 角色：管理员 / 同学 |
| act | 动作：提交 / 归档 / 驳回 / 查看 / 修改 |
| obj | 操作对象（材料名） |
| src | 来源，默认"本机" |

### 6.3 预留扩展（阶段一 / 二新增，不改动现有两表结构）

- 人员表：学号、姓名、班级、联系方式，用于提交带出与缺交核对。
- 任务表：材料类别、截止时间、应交范围、完成状态。
- 远程同步后新增同步状态、最后更新时间等字段，走迁移而非覆盖旧库。

## 七、核心业务流程

```
同学 / 学委提交
      │  必填校验通过，写入 docs（状态=待审核），记日志"提交"
      ▼
   待审核台账 ──查看详情（记日志"查看"，附该材料留痕时间线）
      │
      ├─ 管理员归档 ──► 状态=已归档，记日志"归档"
      └─ 管理员驳回 ──► 状态=已驳回，记日志"驳回"

任意阶段：导出备份（docs + logs）；需要时导入恢复，结构校验失败则回滚不写入。
```

## 八、界面结构

- 左侧侧边栏：品牌区、导航项（材料台账 / 提交材料 / 操作日志）、底部角色切换。
- 右侧内容区：顶部标题与统计概览，下方三视图堆叠，导航切换抬升对应视图。
- 底部状态栏：本地模式提示、材料 / 日志条数、临时反馈文案。

## 九、演进路线（与《接入规划.md》对齐）

1. **阶段一 · 本地打磨**：先把附件落盘、导入导出、审核备注、首页看板、人员名单与缺交核对做扎实。
2. **阶段二 · 平台接入**：选学校在用的一个平台，先只读同步试点，确认字段映射后再开放写入，接附件存储与通知；全程保留切回纯本地的开关。
3. **阶段三 · AI 辅助**：从分类建议切入，验证准确率后再扩齐全度检查、重复识别、文案草稿、检索问答；AI 结果入日志留痕，关键动作人工确认。
4. **阶段四 · 远期**：多人实时协作、手机端、学期归档包、审计导出，确有需求再投入。

## 十、设计原则与约束

1. **离线优先，联网可选**：断网时本地提交、审核、查看、留痕完整可用；联网 / AI 失败回退本地，不卡死、不丢数据。
2. **先本地后云端**：不为用不上的协作功能提前复杂化架构。
3. **可回退、可迁移**：数据可导出，不被单一平台锁死；接口层留开关，能切回本地。
4. **隐私最小化**：学号、姓名等个人信息最小化收集；上传与 AI 调用前评估脱敏，敏感材料保留不出本机的选项。
5. **AI 只建议，不拍板**：分类、摘要、话术由 AI 草稿，归档、驳回等关键动作由人确认。
6. **小步迭代、可回归**：每轮改动跑固定自检，问题用例固化进 `tests/`。

## 十一、边界与不承诺项

- 当前为单机离线版，不保证多人实时一致；多人协作需后续远程方案。
- 附件当前只记录文件名，文件本身未落盘；换电脑后附件打不开。
- 未实现账号登录与分级权限；视角切换为演示性质。
- CSV 导入导出、审核备注、统计看板、名单核对、任务跟踪已落地；网页版 AI 助手已落地，桌面端 AI 入口、Excel 解析与在线收集仍未实现。
- 自检覆盖代码路径与常见边界，不等于所有环境、所有数据组合零缺陷；不同分辨率、字体缩放、长时间运行仍需实机观察。

## 十二、本地主流程验收清单

交付前在本机走通以下链路，任一环节失败视为未通过：

1. 启动程序，台账、统计、日志正常加载，无裸报错弹窗。
2. 填写必填项提交，新材料出现在台账首位，状态"待审核"，日志新增一条"提交"。
3. 缺名称 / 类别 / 姓名时被就地拦截，不写入。
4. 选中材料查看详情，信息完整，详情内显示该材料留痕记录。
5. 归档后状态变"已归档"，日志新增"归档"；驳回后状态变"已驳回"，日志新增"驳回"。
6. 未选中记录时归档 / 驳回按钮不可用或给出提示，不误操作。
7. 导出备份后清空或重建库，导入备份能完整恢复材料与日志。
8. 搜索含 `%` `_` 按字面匹配；脏数据、缺字段记录不导致崩溃。
9. 未捕获异常写入本机 `crash.log`；库文件损坏时隔离重建后仍可启动。
