> 本篇为《通用工作台蓝图-v3.md》的调研支撑：横向摸清主流办公平台在"材料台账、收集表单、审批流转、角色权限、协作通知、附件文件、离线与开放对接"上的做法，再结合本项目现状给出**设计参考优先级**与**未来对接优先级**。

## 三、分组要点与可借鉴点

### 3.1 协同办公套件（飞书 / 钉钉 / 企业微信）

**共性做法**
- **审批中心**：自定义表单＋可配置审批链；节点状态实时可见（待审/通过/驳回）；流程记录自动归档，可按到达时间/处理时间筛选待办与已办；审批模板可由管理助理维护、记录可导出。
- **组织与权限**：分层管理员（超管/子管理员），管理范围限定到部门；通讯录可见范围可配置；权限按"角色＋管理范围"授予。
- **待办聚合**：审批、任务、消息在工作台聚合入口；有独立待办统计。

**对本项目可借鉴**
- 审批节点模型：经办人初审 → 管理者定稿，每节点记人、记意见、记状态；待办/已办分队列并按时间筛选。
- 权限模型：角色 × 管理范围（本组/全部/本人）；管理员分级的思路映射到汇总者/审核者。
- 记录归档与可追溯：每次流转入日志，可导出。

### 3.2 在线文档与表格（WPS / 腾讯文档 / Google）

**共性做法**
- **结构化表格**：字段类型（文本/数字/日期/单选/多选/附件/成员）、分组、筛选、多视图、仪表盘；修改追踪与历史版本回溯；浏览/修订/操作记录留痕。
- **收集表**：由表格生成表单，可限次、限定填写成员范围；工号/学号自动带出姓名部门；数据自动汇总回表。
- **协作权限**：文档级与区域/列级保护；查看/评论/编辑/管理分级；导出、复制、下载可单独管控。

**对本项目可借鉴**
- 列表套件：字段类型意识、分组视图、条件标签、计数、历史版本与留痕时间线。
- 收集环节：学号带出姓名、防重名、限次与范围、催填清单。
- 权限分级映射到界面四档（隐藏/禁用/只读/可操作）。

### 3.3 桌面办公套件（Microsoft 365）

**要点**
- Excel 桌面端可离线，云端共同创作；SharePoint Lists 支持列表项审批与细粒度权限；Planner 任务不支持自定义任务权限，权限继承自 Office 365 组；Teams 任务可加"完成前需经理审批"要求。
- 整体偏重企业组与云端组，高校班级场景渗透低，国内访问与部署成本高。

**对本项目可借鉴**
- 任务－审批联动思路：任务完成可挂审批要求；其余架构不照搬。

### 3.4 低代码/多维表（简道云 / 明道云 / 宜搭 / Airtable）

**要点**
- 表单引擎：丰富字段类型、子表单、跨表联动、计算函数；流程引擎跑通"采集→审批→归档→分析"；仪表盘做汇总分析；角色与数据权限分离。
- Airtable 强在关系库与多视图、关联字段；简道云/明道云强在流程与企业权限；宜搭内嵌钉钉生态。
- 全部为纯云端、订阅制，不满足"本机离线、数据留本机"的现状要求。

**对本项目可借鉴**
- 信息建模方式：对象－字段－关联－视图；表单与流程分离设计；仪表盘指标口径。
- 不照搬其云端架构；作为自研底座的设计参照。

### 3.5 轻量收集工具（接龙管家等）

**要点**
- 微信/QQ 小程序内完成接龙、打卡、填表、签到、投票、文件（图片/Word/Excel）收集；AI 一句话生成表单；名单/按钮两种模式，实时统计、催填、防重名；可分享二维码/海报到群。
- 封闭生态，无开放 API，数据不在本机，无审批与台账管理。

**对本项目可借鉴**
- 收集交互的轻量习惯：一句话/模板起表单、实时看谁没交、一键催填、附件类型提示。
- 定位对照：本项目要做的是"收集之后的台账、审核、归档、追溯"，补上这类工具不做的后半段。

### 3.6 Agent 平台（交互范式参考）

**要点**
- 人在环：敏感动作前弹出审批卡，人工确认后才执行；步骤状态指示（待办/进行中/完成/失败）；审计轨迹可回溯、可逐步重放；意图在左、证据结果在右；非阻塞内联卡片，避免整屏弹窗锁死工作台；待办汇总架常驻。

**对本项目可借鉴**
- 关键动作二次确认与原因记录；状态流转可见；全量留痕可回溯；AI 建议以卡片呈现、人工拍板。

## 四、关键维度横向结论

### 4.1 审批流
成熟做法一致：**表单 → 节点链 → 节点状态 → 意见留痕 → 归档可查**。本项目当前是单层"待审核→归档/驳回"，缺节点拆分。P0 落地"初审 → 定稿"两节点即可，不追求多级会签、或签、加签。

### 4.2 角色权限
成熟做法分两层：**管理范围**（全公司/部门/本组/本人）× **动作权限**（查看/评论/编辑/管理，或录入/审批/配置）。本项目对应四类角色与 11 个权限点，本地单机先做界面裁剪，强制权限留后端。

### 4.3 台账形态
产品形态分三档：电子表格（Excel/Sheets，弱结构）、多维表（字段类型＋多视图＋关联）、低代码应用（表单＋流程＋权限＋仪表盘）。本项目当前介于电子表格与多维表之间，目标形态是**带字段类型、视图、留痕的轻量多维表**，不做完整低代码平台。

### 4.4 收集表单
成熟收集表共性：题型丰富、必填/格式校验、限次与成员范围、学号工号带姓名、防重名、实时统计未交、催填入口。本项目已有名单与缺交清单，待补自动带出、防重名与催填闭环。

### 4.5 协作与通知
在线平台靠实时同步＋消息推送＋@评论；本项目离线阶段无推送，通知以站内待办队列、状态标签、导出催填清单替代；P2 再接外部消息通道。

### 4.6 附件文件
在线平台附件存云盘、可预览/转存/版本管理；本项目当前仅记文件名/路径，文件未落地。P1 先做本机集中目录落地与备份携带，云端附件留 P3。

### 4.7 离线与本地
只有桌面 Office 与本地 WPS 文件支持离线；协同套件与低代码均为云端。本项目离线优先是明确差异点，不能为对齐在线范式而提前上云。

### 4.8 开放对接
飞书/钉钉/企业微信有服务端 OpenAPI、应用授权、Webhook；低代码与在线文档企业版次之；接龙管家封闭。对接层按现有适配器设计，不绑死任一平台。

## 五、高校班级场景的实际习惯

- 班委高频收集发生在 **微信/QQ 群生态**：接龙管家类小程序、群接龙、腾讯文档、WPS 智能表单最普遍；文件、截图、报名表混在聊天记录里。
- 广西已有高校部署 WPS 365 教育版用于社团/班级收集；飞书/钉钉/企业微信更多出现在学院、组织层面的部署，班级学生未必有对应账号体系。
- 学生侧只做提交与查看本人记录；真正的台账、审核、归档、追溯在班委与老师侧——这正是本项目工作台要承接的后半段。

## 六、选型建议

### 6.1 设计参考优先级（自研界面与架构参照）

| 优先级 | 参考对象 | 借鉴内容 |
|---|---|---|
| 第一 | Ant Design Pro 信息架构 | 待办优先首页、导航框架、列表套件、抽屉详情、空态/结果页 |
| 第一 | 飞书多维表 / 腾讯智能表 | 字段类型、分组视图、条件标签、仪表盘、历史溯源 |
| 第二 | 飞书 / 钉钉 / 企微审批 | 审批节点链、节点状态、意见留痕、待办已办队列、管理范围 |
| 第二 | WPS / 企微收集表 | 学号带姓名、限次范围、防重名、催填、题型与校验 |
| 第三 | 简道云 / Airtable | 信息建模、表单与流程分离、仪表盘口径（仅参照，不照搬云端） |
| 第三 | Agent 平台 | 人在环确认、步骤状态、审计轨迹、内联卡片、AI 建议不拍板 |

### 6.2 未来对接优先级（接后端后再排，当前不实现）

1. **先跟随实际在用工具**：上线后观察本班/本院学生与老师实际用什么收集与沟通，再定第一对接对象；不在单机阶段预设平台。
2. **适配器候选顺序**：WPS/金山文档 与 腾讯文档（班级渗透高、国内可达）→ 企业微信/钉钉/飞书（若组织已部署、有账号体系）→ 消息通知 Webhook。Google Workspace、Microsoft 365、Airtable 国内班级场景优先级低。
3. **对接节奏**：只读同步试点 → 字段映射确认 → 开放写入与附件云存；全程保留切回纯本地开关。

### 6.3 明确不做的选择

- 不把本项目做成某个在线平台的套壳或前端页面；本地离线闭环是底座能力。
- 不照搬低代码平台的完整建模与云端权限体系；本期只取其字段/视图/流程思路。
- 不提前实现多人实时协作、云端附件、外部消息推送；这些依赖后端，列入 P3 评估。
- 不接入无开放 API 的封闭小程序作为数据源；仅借鉴其收集交互。

## 七、回扣到蓝图路线

| 路线 | 来自调研的补强点 |
|---|---|
| P0 底座与岗位模型 | 审批节点链参照飞书/钉钉；权限"范围×动作"参照套件管理范围；首页待办队列参照 Pro 与工作台聚合 |
| P1 专项补全 | 收集表借鉴学号带姓名、防重名、限次范围；附件本机落地参照云盘文件管理的目录/版本思路；列表借鉴多维表字段类型与分组 |
| P2 对接与 AI | 适配器先对接高渗透在线文档；AI 建议走 agent 人在环范式，卡片确认、留痕可追溯 |
| P3 多人协作 | 参照套件实时协作与云附件；权限强制、账号体系、跨端一致 |
