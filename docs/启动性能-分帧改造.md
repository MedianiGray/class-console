# 启动性能：分帧启动改造（0.27.2 待打包）

状态：代码已落地并通过回归，**尚未在 Windows 打包复测**，因此不进入任何“已达标”口径。

## 一、改了什么

1. **分帧启动（`main.py` + `ui_main.py`）**
   - `MainWindow(master, repo, staged=True)`：只建顶栏、侧栏、标题栏与状态栏，内容区先放一张占位卡（“正在载入工作台…”）。
   - 窗口按最终尺寸居中、`update` 出首帧后，用 `root.after(1, …)` 在主循环里补当前视图，不再让首帧等完整界面。
   - `start_content()` 幂等；`switch()` 在占位期被调用时先置“内容已就绪”再撤占位，中途跳转不会留下占位卡。
   - **占位卡在视图建完之后才撤**，中间不出现空白帧。
2. **看板空态按需创建（`ui_dashboard.py`）**
   - “没有材料 / 没有动态”两个空态原来启动即建（共 16 个控件），改为 `doc_empty` / `log_empty` 首次需要显示时才建。
3. **类别分布与近期动态行复用（`ui_dashboard.py`）**
   - 原来每次 `refresh()` 都 `destroy` 全部子控件重建（约 38 个控件）；改为行只建一次，刷新时只改文字、数字与横条比例。切页、入账、改状态都不再重复付构建成本。

## 二、实测一：Windows 11 最终包（发布口径）

便携目录版最终包（Python 3.14 + Tk 9），`tests/perf_portable.py` 同时计“窗口可见”和“内容就绪”：

| 口径 | 窗口可见 | 内容就绪 |
| --- | --- | --- |
| 同机已有数据（5 次） | 977.5 / 977.6 / 977.8 / 1032.1 / 1080.8ms，中位 **977.8ms** | 中位 1514.9ms |
| 干净目录首次 | 2466.0ms | 2969.2ms |
| 单文件版（3 次） | 中位 4403.2ms | 中位 4908.8ms |

对照 v0.27.1 便携版 2078.1ms（只计进主窗口）：窗口可见约快一倍多，干净首次 3906.7ms → 2466.0ms。**内容就绪仍未进入 1 秒，门禁继续记未完全达标。**

## 三、实测二：云主机 Linux（`/usr/bin/python3.10` + Xvfb，仅作结构性参考）

`tests/startup_bench.py` 已改成分段口径：外壳 = 顶栏/侧栏/占位；内容 = 当前视图补齐。

| 口径 | 窗口可见 | 内容就绪 |
| --- | --- | --- |
| 干净首次 | 650ms | 1313ms |
| 已有数据（3 次中位） | 504ms | 1142ms |

真实入口 `CC_STARTUP_TRACE` 同口径：`loading-shell-painted 175` → `repository-ready 189` → `window-shell-built 655` → `window-shell-painted 669` → `content-start 670` → `content-ready 1317`。

改造前（一次性建完再显示）：干净首次合计 1276ms、已有数据 1182ms 才有第一帧。也就是说**用户看到窗口的时间提前了约一半**（1.2–1.3s → 0.5–0.65s），内容就绪时间基本持平（+50ms 左右的额外绘制）。

## 四、边界与不能说的数字

- **1 秒目标仍未达成**，任何文档、Release 正文、落地页都不能写“已达标”。
- 云主机这套 Tk 字体栈有一处明确的性能特征：**给控件显式设 `font` 时，每个控件约 9ms；不设 `font` 约 0.2ms**（同一进程内 A/B、`font=` 与 `configure(font=…)`、元组与命名 `Font` 对象都复现）。这让 Linux 上的“按控件计时”严重失真，不能直接当成 Windows 数字，也不能据此推到“排版导致慢”的结论。
- 因此本次只记录**结构性收益**（少建控件、早出首帧），量化收益以 Windows 重打包后的 `tests/perf_desktop.py` / `tests/perf_portable.py` 为准。

## 五、下一步的杠杆（按性价比）

1. **继续减少控件数**：类别分布 6 行 × 4 控件可合并为一张 Canvas 一次绘制；近期动态 4 行 × 5 控件同样可以合并。
2. **外壳瘦身**：顶栏 20 控件、侧栏 40 控件是目前单块最重的两段，可按“图标栏优先、文字后补”再分一层。
3. **打包层**：onedir 已把解包成本去掉，剩下的是 Python 解释器 + Tk 启动（约 0.6s）与主窗口构建，1 秒内必须把窗口构建压到 0.3s 级。
