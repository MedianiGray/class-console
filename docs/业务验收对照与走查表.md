# 业务验收对照与走查表

> 用途：逐条核对"已实现功能是否达标"，区分**本机自测通过**与**待业务方实机确认**；并提供一份可照着走的试用步骤。
> 当前版本：v0.2.1（本地打磨版）。本表只做现状对照，不代表商业级大规模验证结论。

## 一、总体结论

- **已验证**：本地主流程闭环（看板 → 台账 → 提交 → 审核 → 归档/驳回 → 留痕 → 备份恢复），数据层 14 项自检与 GUI 冒烟在本机通过，exe 首启存活、种子数据正确、无崩溃日志。
- **未确认**：程序在老师/同学真实使用场景下是否顺手、是否贴合收材料的业务习惯，尚未经过业务方试用。
- **未实现**：缺交核对、人员名单、任务截止跟踪、附件落盘、表格导入导出、审核备注等业务高频能力（见第三节）。
- **指标现状**：目前只测了技术链路指标；业务指标口径与合格线尚未定义、未在真实数据上测量。

## 四、核对中发现的待修一致性问题

1. **查看留痕的操作人口径**：查看详情时，日志操作人记成了材料提交人；归档/驳回记的是当前操作者。两类动作的操作人口径不统一，需对齐为"当前操作者"。
2. **搜索不覆盖学号**：台账搜索仅匹配材料名与姓名，业务上常按学号找人，需补入学号匹配。
3. **统计口径**：主窗口状态栏只显示总数/待审核/已归档；驳回数在看板卡片单独统计，口径可再统一。

## 六、实机走查步骤（给老师 / 学委试用）

> 在本机用真实（或脱敏）材料逐条走，每步在"结果"栏记 通过 / 卡点。

1. **首启**：打开程序，看板加载正常，条数与台账一致，无报错弹窗。
2. **同学提交**：填一份完整材料提交，确认新材料出现在台账首位、状态"待审核"，日志新增一条"提交"。
3. **校验拦截**：分别试缺材料名、缺类别、学号填字母，确认被就地拦下、不写入台账。
4. **查看详情**：选中材料双击/回车查看，信息完整，详情内显示该材料操作记录。
5. **归档**：管理员视角选中待审核材料归档，状态变"已归档"，日志新增"归档"。
6. **驳回**：再选一条驳回，状态变"已驳回"，日志新增"驳回"。
7. **筛选搜索**：分别按类别、状态、姓名/材料名筛选；试按学号查找（当前可能搜不到，记为卡点）。
8. **备份恢复**：导出 JSON 备份，清空后导入，核对材料与日志完整恢复。
9. **视角切换**：切到同学视角，确认看不到归档/驳回入口。
10. **卡点记录**：把找不到、卡住、不顺手、希望增加的功能记下来，作为下一轮迭代依据。

## 七、尚未覆盖的验证环境与边界

- 未在老师本人电脑（不同 Windows 版本、分辨率、字体缩放）上实机运行。
- 未做长时间挂机、大批量材料（上百条以上）下的表现观察。
- 角色切换为演示性质，未接账号登录与真实分级权限，不能据此认为已防越权。
- 附件未落盘，换电脑后历史附件打不开；当前仅记录文件名。
- 外部对接、AI、多端协作均为规划，不在本版可用范围内。
