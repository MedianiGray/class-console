# 业务验收对照与走查表

> 用途：逐条核对"已实现功能是否达标"，区分**本机自测通过**与**待业务方实机确认**；并提供一份可照着走的试用步骤。
> 当前版本：网页版 v0.25.0 / 桌面端 v0.23.0（对齐版）。v0.25.0 改网页 AI 入口与首屏结构，业务口径、权限与数据层沿用 v0.23.0 基线；本表只做现状对照，不代表商业级大规模验证结论。

## 一、总体结论

- **已验证**：本地主流程闭环（看板 → 台账 → 提交 → 审核 → 归档/驳回 → 留痕 → 备份恢复），并已补上免交 / 延期、催交限频、同学回执、服务留痕、届别交接包、文件室、网页版 AI 副驾与完整助手、两端首次引导、空态统一、错误恢复路径与跨端侧栏同构。桌面数据层 44 项自检、GUI 冒烟 24 段、网页冒烟 228 项在本机通过。
- **未确认**：程序在老师 / 同学真实使用场景下是否顺手、是否贴合收材料的业务习惯，尚未经过业务方试用。
- **已补齐**：人员名单与缺交核对、审核 / 驳回备注、台账 CSV 导入导出、任务 / 截止跟踪、文件夹收集、审计证据包、服务跟进与交接、归档文件室、网页版 AI 助手。
- **未实现**：外部平台对接、网页链接识别、桌面端 AI 入口（见 B9–B11）；文件室为桌面专属，网页版不提供。
- **指标现状**：已补 A4 5000 条数据基线。网页首屏、筛选、滚动与 JS 堆通过；桌面数据层查询与常驻内存通过，台账刷新与冷启动未达标。测试机、脚本、三次中位数与未达标原因见第五-A 节。

## 五-A、A4 5000 条性能基线（2026-11-25）

### 测试机与口径

| 项 | 值 |
| --- | --- |
| 系统 | Windows 10 专业版 10.0.19045 |
| CPU | Intel Core i5-8250U，4 核 8 线程，1.60GHz |
| 内存 | 8GB |
| Python | 3.12.8 |
| 浏览器 | Microsoft Edge Headless 158.0.0.0 |
| 版本 | 网页 v0.25.0 / 桌面 v0.23.0（对齐版） |

- 每项三次独立运行取中位数；本轮计时期间本机仍有日常后台程序，未清场。
- 网页：`node tests/perf_web.js`。把 `web/index.html` 复制到本机临时目录，启动独立 Edge 配置，注入 5000 条材料；按每页 50 条测首屏、筛选与页面滚动。首屏取 DOMContentLoaded 与 First Contentful Paint 的较大值。
- 桌面：`python tests/perf_desktop.py`。临时 APPDATA + 临时 SQLite 写 5000 条材料、5000 条日志；源码与打包 EXE 各起三次，统计到主窗口的时间与常驻内存。

### 网页结果

| 指标 | 目标 | 实测 | 判定 |
| --- | --- | --- | --- |
| 本地文件首屏可交互 | ≤1s | 424ms（dcl 396.5 / fcp 424；三轮 398–421ms） | 通过 |
| 5000 条全部渲染 | ≤100ms | 23.1ms | 通过 |
| 5000 条关键词筛选 / 类别+状态筛选 | ≤100ms | 24.3ms / 32.9ms | 通过 |
| 5000 条滚动 | 无明显掉帧 | 每页 50 条，58.5fps，p95 帧间隔 16.8ms | 通过 |
| 标签页内存 | ≤150MB | JS 堆 9.5MB；整页渲染进程私有工作集 133.6MB（空白页 143.4MB） | 应用堆通过；整页绝对值待复核 |

- 5000 条不会同时进入滚动区；网页保留每页 10 / 25 / 50 条的分页，滚动指标按每页 50 条的页面滚动测量，不把 Node 模拟当成浏览器滚动。
- 整页私有工作集在另一次重复测到 177.9–181.6MB；headless Edge 自身空白页基线已约 143MB，绝对值受内核预载与后台任务影响，不能作为稳定的页面预算。后续需在非 headless Chrome / Edge 复核。

### 桌面结果

| 指标 | 目标 | 实测 | 判定 |
| --- | --- | --- | --- |
| 5000 条全部查询 | ≤100ms | 87.5ms | 通过 |
| 5000 条关键词 / 类别筛选 | ≤100ms | 8.2ms / 20.4ms | 通过 |
| 统计 / 日志查询 | ≤100ms | 7.1ms / 56.4ms | 通过 |
| 常驻内存 | ≤150MB | 64.7MB | 通过 |
| 5000 条台账刷新 | ≤100ms | 353.4ms（最慢 627.3ms） | 未通过 |
| 源码冷启动到主窗口 | ≤1s | 5351.3ms（三次 6376.5 / 5179.4 / 5351.3） | 未通过 |
| 打包 EXE 冷启动到主窗口 | ≤1s | 10587.7ms（三次 10587.7 / 10843.9 / 9297.4） | 未通过 |

### 未达标原因、影响与下一轮优化项

- **台账刷新**：SQL 查询只占 87.5ms，主要耗时在 Tk `Treeview` 一次性删除并重建 5000 行。影响是 5000 条时每次改筛选都有约三分之一秒的停顿。下一轮改分页或虚拟列表，保留全量计数与跨页批量操作。
- **源码启动**：首次建表约 1.3s，主窗口一次性构建全部视图约 1.5s，Tk 首次布局约 0.3s。下一轮合并 `_init_db()` 建表语句、延迟构建非当前视图。
- **打包启动**：PyInstaller onefile 首次解包与 Windows 安全扫描占主要时间，约 9.3–10.8s。下一轮评估 onedir 或启动器方案；不把 onefile 的 1s 目标当成已达成。
- 本轮不因性能引入第三方大依赖；未达标项保留在 A4 下一轮，不用假数据或改口径掩盖。

## 六、实机走查步骤（给老师 / 学委试用）

> 在本机用真实（或脱敏）材料逐条走，每步在"结果"栏记 通过 / 卡点。

1. **首启**：打开程序，看板加载正常，条数与台账一致，无报错弹窗。
2. **同学提交**：填一份完整材料提交，确认新材料出现在台账首位、状态"待审核"，日志新增一条"提交"。
3. **校验拦截**：分别试缺材料名、缺类别、学号填字母，确认被就地拦下、不写入台账。
4. **查看详情**：选中材料双击/回车查看，信息完整，详情内显示该材料操作记录。
5. **归档**：管理员视角选中待审核材料归档，状态变"已归档"，日志新增"归档"。
6. **驳回**：再选一条驳回，状态变"已驳回"，日志新增"驳回"。
7. **筛选搜索**：分别按类别、状态、姓名/材料名/学号筛选定位。
8. **服务跟进**：名单核对 → 完成矩阵，选一名未交学生生成催交话术；登记回执后确认矩阵变「回执·已交 / 校外 / 稍后」，且 24 小时内再次催交被拦。
9. **免交 / 延期**：登记一条延期并填未来截止日，确认矩阵显示「延期」；把截止日改到过去应被拒绝。
10. **服务留痕**：打开「服务留痕」，核对四张卡与刚产生的催交 / 回执 / 延期记录，导出 CSV 能用 Excel 打开。
11. **交接包**：设置 → 数据 → 导出交接包，解开 ZIP 确认含数据备份、交接说明、manifest；再导入一次，确认先出摘要与覆盖预览。
12. **备份恢复**：导出 JSON 备份，清空后导入，核对材料、日志、名单、任务与服务记录完整恢复。
13. **视角切换**：切到同学视角，确认看不到归档 / 驳回与服务跟进入口。
14. **文件室**：打开「文件室」，按目录树找到一条已归档材料，确认右侧能看到图片 / PDF 缩略图或文本前 200 字；点「去台账」能回到对应材料。再拖入一个文件，确认落到当前目录、状态为待审核、同名不覆盖。
15. **缺失反查**：在「文件室」顶部点「缺失文件」，确认清单带学生与编号；双击可回台账，源文件仍在时「重新归位」能补齐。
16. **卡点记录**：把找不到、卡住、不顺手、希望增加的功能记下来，作为下一轮迭代依据。

## 七、尚未覆盖的验证环境与边界

- 未在老师本人电脑（不同 Windows 版本、分辨率、字体缩放）上实机运行。
- 未做长时间挂机；5000 条数据的首屏、筛选与滚动已有 A4 基线，但桌面台账刷新与冷启动未达标。
- 角色切换为演示性质，未接账号登录与真实分级权限，不能据此认为已防越权。
- 附件在桌面端可随归档复制落盘；网页版受浏览器边界限制仍只记录文件名。
- 外部平台对接、多端协作仍为规划；AI 仅在网页版可用，桌面端尚未接入。
- 网页版 AI 的 API 通道未用真实 Key 做过跨域实测；本地模型在低配设备上首次下载较慢，手机端体验有限。
- 文件室依赖本机目录与 Windows Shell 缩略图，仅桌面版提供；PDF / Office 缩略图取不到时回退为系统打开，不阻断登记与查找。
- v1.0 静默版的首次引导、空态 / 错误态已补齐；性能基线已建立，桌面优化项与安装包说明尚未完成。
