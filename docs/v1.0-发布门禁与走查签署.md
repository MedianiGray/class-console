| 常驻内存 | ≤150MB | 38.4MB | 通过 |
| 源码冷启动（已有数据） | ≤1s | 中位 1836.1ms | **已知例外** |
| 打包 EXE 冷启动（已有数据） | ≤1s | 中位 3050.5ms | **已知例外** |
| 首次建库（源码 / 打包） | 记录项 | 2045.2 / 2830.0ms | 记录 |

例外口径：台账刷新是 300 条首屏 + 按需加载，不是一次性渲染 5000 行；冷启动瓶颈是 Tk 固定开销与 onefile 解包，不是数据库。v0.27.0 复测源码 1.8s、打包 3.0s，均高于 1s；打包已比 v0.26 的 10.6s 明显下降。发布说明、README、业务验收表必须同时保留例外，不得写成已达标。若业务方不接受该例外，本项阻塞发布，下一轮先做 onedir / 启动器或首屏外壳减负。

## 四、发布动作（签字后执行）

1. 升 `version.py` 与网页版本 / SW 缓存名，更新 README、CHANGELOG、发布说明。
2. 全量复跑：网页 264 + 五个浏览器冒烟 + PWA 更新链；桌面 45 + GUI + 分页 + AI 40。
3. 打包新版 EXE，干净目录启动，记录文件名、字节数、SHA256 与冷启动。

5. 同步 Pages 网页、落地页与线上 SW；浏览器实机核对首导与更新提示。
