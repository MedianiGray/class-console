## 1. 执行项

### A1 首次引导：网页 + 桌面

**状态：已完成（v0.21.0，2026-11-24）**

**要解决**：新用户第一次打开，不知道先做什么；网页只在空台账出现三步，桌面完全没有。

**做法**
- 不弹欢迎弹窗，不做多页 tour。首屏顶部放一张可收起的「三步上手」卡：
  1. 录入或收集第一份材料
  2. 审核并归档，看到第一条留痕
  3. 核对名单 / 登记任务
- 每一步有状态：未开始 / 已完成 / 跳过；完成第一份归档后，第 1、2 步自动打勾。
- 首次标记存本机；网页 `FIRST_RUN_KEY`，桌面存本机配置。刷新、重开不重复弹。
- 卡片右上角「收起」；网页收进「更多 → 使用帮助」，桌面收进「设置 → 使用帮助」，不删除入口。
- 申请人视角只显示「填写学号 → 提交材料 → 查看进度」，不显示审核与名单步骤。

**涉及**
- `web/index.html`：首屏渲染、`localStorage` 首次标记、帮助入口。
- `ui_main.py`：概览页首次引导卡、本机配置读写。
- `docs/使用说明.md`：首次使用一节。

**已落地**
- 网页：`FIRST_RUN_KEY` 存本机；种子数据加 `demo` 标记，首导进度只认真实材料、真实归档、真实名单/任务；卡片可收起，从「更多 → 使用帮助」重看；空库且已收起时保留一个简单空态，不出现空白首屏；示例数据可一键清空。
- 桌面：`DashboardView` 顶部三步卡；`theme` 存 `first_run_steps / first_run_done / first_run_dismissed`；提交、归档成功后写步骤，完成前两步自动收起；设置底部提供「使用帮助」入口，可重新显示在概览。
- 申请人：两端都只显示「填写学号 → 提交材料 → 查看进度」，不显示审核与名单步骤。
- 老用户：两端若已有真实材料且没有首导标记，静默视为已完成，不打扰；桌面以「材料多于种子」判定老库。

**验收**
- 全新浏览器配置打开网页，首屏出现三步卡，无弹窗链。
- 从空库完成一次提交 → 审核 → 归档，计时 ≤3 分钟。
- 刷新后不重复出现；网页从「更多 → 使用帮助」、桌面从「设置 → 使用帮助」可再次打开。
- 桌面全新数据目录同样出现，完成一次归档后自动收起。

### A2 空态统一

**要解决**：有的地方是完整空态，有的只有「暂无数据」，新用户不知道下一步。

**统一格式**
```
标题：这一屏还没有什么
说明：为什么空 / 空代表什么
主动作：下一步做什么（一个实心按钮）
次动作：可选，文字链
```

**覆盖视图**
- 概览：空库 / 无待办 / 无权限
- 材料台账：空库 / 无筛选结果 / 申请人未填学号
- 提交材料：无草稿 / 附件读取失败
- 名单核对：空名单 / 全员已交
- 任务跟踪：无任务 / 无临期
- 材料模板：无扩展字段
- 操作日志：无日志
- 文件夹收集：未选目录 / 浏览器不支持
- AI 助手：未配置 / 模型未加载
- 文件室（桌面）：未设归档根 / 空目录

**规则**
- 不用裸「暂无数据」；空态必须给下一步。
- 无权限不伪装成空态：写清「当前视角无权查看，切换到 X 岗位」。
- 空态不占整页：表格类留在表体位置，面板类留在面板位置。
- 申请人未填学号时，不显示任何他人数据，也不显示假统计。

**状态：已完成（v0.21.1，2026-11-24）**

- 网页端新增通用 `emptyState()` / `emptyBtn()`，覆盖看板、台账、名单、任务、日志、模板字段、保存视图、详情抽屉、命令面板、AI 助手、文件夹收集；空态按钮分别执行切视图、聚焦输入、清空筛选、打开新增弹窗等真实动作。
- 桌面端新增 `ui_empty.py` 统一 `EmptyState`，覆盖看板、台账、名单与矩阵、任务、日志、文件室、服务留痕、文件夹收集；`ui_main._role_menu()` 支持无事件调用，空态「切换岗位」可直接弹出岗位菜单。
- 去假成功态：名单为空时不再显示「所有人都已提交材料」；申请人未填学号不显示任何他人数据。
- 文件夹收集补读取失败态：单个文件读不出来时显示失败数量、原因说明与「重新扫描」，不再把全部读取失败误判成空目录。
- 提交材料是单页表单 + 本地草稿，没有草稿列表，因此「无草稿」不单独造空态；附件只登记文件名与路径、不读文件内容，读取失败统一归文件夹收集与 A3 错误态处理。
- 回归：Web 199、桌面数据 39、GUI 22 段；`py_compile` 通过。

**验收**
- 逐视图走查，所有空态都有标题、说明、主动作。
- 全局检索 `暂无数据`、`暂无`，不得出现无说明的裸文案。
- 空态按钮全部可点、可到达；不出现僵尸按钮。

### A3 错误态与恢复路径

**要解决**：存储失败、导入失败、目录权限、AI 失败目前多处静默吞掉，用户不知道发生了什么。

**统一错误四段**
```
发生了什么：一句人话
影响范围：哪些数据没保存 / 哪些操作没完成
下一步：一个可执行动作
兜底：导出备份 / 重试 / 换浏览器 / 联系维护者
```

**必须覆盖**
| 场景 | 现在的问题 | 收口要求 |
| --- | --- | --- |
| localStorage 被禁用 | 静默降级内存态 | 顶部常驻条：本次可继续，刷新会丢；先导出备份 |
| localStorage 配额满 | `catch(e){}` 吞掉 | 提示容量满、影响范围、导出后清理 |
| 备份 JSON 损坏 | 有校验，但提示不完整 | 不覆盖现有数据，指出哪段结构不对 |
| 导入预览不匹配 | 有预览，但缺恢复路径 | 明确「未写入」，给重选文件入口 |
| 文件夹权限拒绝 | 浏览器行为差异大 | 说清支持浏览器，降级一次性读取 |
| AI API / 模型失败 | 有错误气泡，但恢复弱 | 保留本地功能，给改配置 / 换模型入口 |
| 归档写盘失败 | 桌面有异常捕获 | 原件不删，给重试与目标目录检查 |
| 未捕获异常 | `crash.log` 有 | 设置页给「导出崩溃日志」入口 |

**代码要求**
- 禁止新增空 `catch`；至少 `console.warn` + 用户可见提示。
- 瞬时错误用 toast；表单错误就地显示；存储/权限用顶部条；破坏性操作才用模态。
- 错误提示不得暴露堆栈、路径中的用户名、API Key。

**验收**
- 用开发者工具模拟 `localStorage.setItem` 抛异常，页面不白屏，出现常驻提示与导出入口。
- 导入损坏备份，现有数据不变，提示可执行。
- 拒绝文件夹权限，页面给出降级路径，不反复弹窗。
- AI 断网/错 Key，材料主流程不受影响。

**状态：已完成（v0.22.0，2026-11-24）**

- 网页端新增顶栏常驻 `#storageNotice`：存储被禁用或配额满时说明影响范围，提供「导出备份 / 重试写入」；损坏缓存保留原文、不再回写覆盖，提供「下载原缓存 / 清除并重载」。
- 备份增加 `app` / `version` / `exportedAt` / `counts`，导入前校验应用标识、数组结构、逐条记录与声明条数；不匹配四段弹窗说明「未写入」，给「重选文件 / 导出当前数据 / 取消」。
- 文件夹权限或读取失败改为错误态，提供「重新授权文件夹 / 换一个文件夹 / 重新扫描」，逐文件失败只报剩余数量，不反复弹窗。
- AI 失败分类为无 Key、401/403、404、429、5xx、WebGPU/显存、跨域断网、模型加载与空返回；只显示安全文案，不回显接口回包、Key 或 Bearer。
- 桌面端新增 `ui_error.py` 四段对话框；`archive.place()` 返回 `ok` 与脱敏原因，归档失败不再当成功；批量入账失败只说明一次；备份恢复先比对元数据与记录格式。
- 桌面损坏数据库隔离改名后重建，并在开机说明原库位置；`_init_db()` 异常关闭连接，避免 Windows 文件锁导致隔离失败。
- 启动失败、`sys.excepthook` 与 Tk 回调异常统一写 `crash.log`，界面给「导出崩溃日志 / 继续使用」；设置 → 关于新增导出入口。
- 回归：Web 212、桌面数据 44、GUI 23 段；`py_compile` 通过。浏览器实机模拟 `QuotaExceededError`，常驻条出现、现有数据未清空。

### A4 性能基线

**要解决**：蓝图写了指标，但没有测过，也没有 5000 条数据场景。

**指标**
| 端 | 指标 | 目标 |
| --- | --- | --- |
| 网页 | 本地文件首屏可交互 | ≤1s |
| 网页 | 5000 条材料筛选 | ≤100ms |
| 网页 | 5000 条滚动 | 无明显掉帧 |
| 网页 | 标签页内存 | ≤150MB |
| 桌面 | 冷启动到主窗口 | ≤1s |
| 桌面 | 5000 条查询/筛选 | ≤100ms |
| 桌面 | 常驻内存 | ≤150MB |

**做法**
- 新增 `tests/perf_web.js`：生成 5000 条种子，计时筛选、渲染、搜索。
- 新增 `tests/perf_desktop.py`：临时 SQLite 写 5000 条，计时查询与统计。
- 记录测试机配置、版本、三次取中位数；结果写入 `docs/业务验收对照与走查表.md`。
- 不达标先定位瓶颈：虚拟列表、分页、索引、避免整表重建；不为性能引入大依赖。

**验收**
- 两项脚本可重复运行，输出通过/不通过。
- 指标达标，或写明未达标原因、影响与下一轮优化项；不虚报。

**状态：基线已建立（v0.23.0，2026-11-25；存在未达标项）**

- 新增 `tests/perf_web.js`：把 `web/index.html` 复制到本机临时目录，启动独立 Edge headless 配置，CDP 注入 5000 条材料，按每页 50 条计时首屏、筛选与页面滚动；三次独立进程取中位数。应用内存记 JS 堆，整页渲染进程私有工作集另记参考值。
- 新增 `tests/perf_desktop.py`：临时 APPDATA 与临时 SQLite 写 5000 条材料、5000 条日志，计时 `list_docs / list_logs / stats`，再用真实 Tk 台账刷新 5000 行；源码与打包 EXE 各起三次，统计到主窗口时间与常驻内存。
- 测试机：Windows 10 专业版 10.0.19045；Intel Core i5-8250U，4 核 8 线程，1.60GHz；8GB 内存；Python 3.12.8；Edge Headless 158.0.0.0。计时期间本机仍有日常后台程序，未做清场。
- 网页结果：首屏 424ms（dcl 396.5 / fcp 424，三轮 398–421ms）；5000 条全部渲染 23.1ms；类别+状态筛选 32.9ms；关键词筛选 24.3ms；50 条/页滚动 58.5fps，p95 帧间隔 16.8ms；JS 堆 9.5MB。四项按应用口径达标。
- 网页内存备注：整页渲染进程私有工作集本轮 128.0–138.0MB（中位 133.6MB），空白页基线 143.4MB；另一次重复测到 177.9–181.6MB。该绝对值受 headless Edge 内核、预载与后台任务影响，不能当成稳定页面预算；后续需在非 headless 浏览器复核。
- 桌面结果：全部查询 87.5ms、关键词 8.2ms、类别 20.4ms、统计 7.1ms、日志 56.4ms，均 ≤100ms；常驻内存 64.7MB，≤150MB。
- 桌面未达标：
  - 5000 条台账刷新 353.4ms（最慢 627.3ms，目标 ≤100ms）。瓶颈在 Tk `Treeview` 一次性重建 5000 行，SQL 查询只占其中约 87.5ms。
  - 源码冷启动到主窗口 5351.3ms（三次 6376.5 / 5179.4 / 5351.3）。`LocalRepository` 首次建表约 1.3s，`MainWindow` 构建全部视图约 1.5s，Tk 首次布局约 0.3s。
  - 打包 EXE 冷启动到主窗口 10587.7ms（三次 10587.7 / 10843.9 / 9297.4）。PyInstaller onefile 首次解包与 Windows 安全扫描占主要时间。
- 下一轮优化项：桌面台账改为分页或虚拟列表，保留全量计数与跨页批量操作；`_init_db()` 合并建表语句；主窗口次要从视图延迟构建；发布包评估 onedir 或启动器方案。不为性能引入第三方大依赖。

### A5 桌面端同步「更多功能」

**要解决**：网页 v0.20.1 已把辅助项收进「更多功能」，桌面仍是平铺，跨端不一致。

**做法**
- 桌面侧栏同步为：办理材料 / 跟进核对 / 更多。
- 「更多功能」收纳现有的文件夹收集、操作日志；按权限显隐。
- 桌面没有 AI，不为了对齐硬塞 AI；「更多」有几项就显示几项。
- 折叠侧栏时显示三点图标，数量角标隐藏；当前页高亮联动。
- 不改变现有视图和权限逻辑，只改入口组织。

**验收**
- 桌面侧栏不再平铺辅助项；「更多」角标数量正确。
- 点击空白处关闭弹窗；选择工具才跳转。
- 申请人视角不显示收集与日志。
- 桌面自检与 GUI 冒烟新增对应断言。

**状态：已完成（v0.23.0，2026-11-25）**
- 侧栏实际为「办理材料 / 跟进核对 / 更多」；整理者（handler / reviewer）与汇总者（manager）看到收集、日志两项，数量角标为 2；申请人两项都不可见，因无可用项而不显示「更多」空入口。
- 「更多功能」为模态弹窗，标题、说明、图标、用途、当前标签与「打开」按钮均为真实内容；点条目跳转并关闭，点窗外空白关闭，`Esc` 关闭。
- 折叠后只留「···」，数量角标不创建；当前页为收集或日志时，三点入口保持主色高亮，`_nav_eyebrow()` 显示「工作台 · 更多」。
- 权限点补 `docs:collect` 并用于收集入口，与网页权限表一致；申请人仍只有填写与提交，不再误见文件夹扫描。
- GUI 冒烟 24 段通过，新增断言覆盖分组、角标、权限显隐、弹窗真实跳转、点外关闭、折叠三点与高亮；桌面数据自检 44、网页冒烟 212 同时通过。

### A6 安装包与首启说明

**要解决**：README 指向 v0.19.0 Release，发布说明写 v0.19.0，打包产物叫 `班级操作台.exe`，下载附件叫 `class-console-v0.19.0.exe`，口径不统一。

**做法**
- 统一产物名：`class-console-v0.21.0.exe`。
- `build_exe.bat` 从 `version.py` 读版本，产物自动带版本；不再手写死版本。
- 发布说明统一：下载、校验、首启、数据位置、卸载、SmartScreen 提示。
- 每次发布附 `SHA256` 校验值；仓库不提交 exe。
- 安装包不含本机数据、日志、`_backup`、测试临时文件。
- 首启说明写清：数据存 `%APPDATA%\ClassConsole`；换机用备份导出/导入；网页与桌面数据不互通。

**验收**
- 干净目录双击 exe，窗口标题带 `v0.21.0`，可完成提交 → 归档 → 导出备份。

### A7 回归与验收测试

**要解决**：首导、空态、错误态、更多入口目前没有足够断言，容易改坏。

### A8 文档与口径同步

**要解决**：多份文档版本、测试数、入口名不一致，用户和后来人会被误导。

**必改**
- `README.md`：当前版本、下载链接、打包命令、网页/桌面关系。
- `release/发布说明.md`：当前版本改为 v0.21.0，补校验与首启。
- `docs/使用说明.md`：首次使用、空态含义、错误恢复、更多功能入口。
- `docs/业务验收对照与走查表.md`：版本、回归数、性能结果。
- `CHANGELOG.md`：新增 `0.21.0 — 静默版收口`。
- `docs/最佳形态蓝图-v1.0.md`：开头仍写 v0.14.1，改为指向当前版本与 v2.0 蓝图。

**验收**
- 全局检索版本号，除历史 CHANGELOG 外无过期“当前版本”。
- 文档中的入口名与界面一致：`更多 → 更多功能 → 工具名`。
- 测试数、性能数、发布附件名三处一致。

### A9 发布门禁

**发布前必须全过**
1. 范围未溢出：没有新增场景包、没有新增侧栏主入口、没有接外部工具。
2. 网页回归 ≥200 通过，桌面自检 + GUI 冒烟通过。
3. 性能有记录，达标或写明例外。
4. EXE 在本机启动，完成主流程，窗口标题版本正确。
5. 发布附件 SHA256 已生成，包内无用户数据。
6. README / 发布说明 / 使用说明 / CHANGELOG 口径一致。
7. GitHub Pages 线上版本与本地一致，浏览器实机核验首导与更多入口。
8. 打 tag、发 Release、上传附件；旧版本保留，不覆盖。

## 2. 执行顺序

| 顺序 | 项 | 原因 |
| --- | --- | --- |
| 1 | A1 首次引导 | 直接决定 3 分钟首条归档 |
| 2 | A2 空态统一 | 首导之后，所有入口都要能接住新人 |
| 3 | A3 错误态 | 不让人在失败时丢数据、被卡死 |
| 4 | A5 桌面更多入口 | 跨端外壳先一致，后面测试才有同一基线 |
| 5 | A4 性能基线 | 功能收口后测，避免边改边测 |
| 6 | A6 安装包 | 性能与主流程稳定后再打包 |
| 7 | A7 回归 | 全量跑，补断言，修回归 |
| 8 | A8 文档 | 以最终实现为准回填 |
| 9 | A9 发布 | 门禁全过才发 |

## 3. 3 分钟验收脚本

1. 清理浏览器站点数据，打开网页版。
2. 首屏出现三步卡；不弹欢迎弹窗。
3. 点「录入第一份材料」，填写一条材料并提交（≤60 秒）。
4. 切到经办人，打开台账，审核并归档（≤60 秒）。
5. 回到概览，第 1、2 步打勾，出现第一条留痕入口（≤30 秒）。
6. 刷新页面，三步卡不再自动展开；从「更多 → 使用帮助」能重新打开。
7. 全程无弹窗套弹窗；只有归档确认一次。
8. 桌面版重复 2–7，数据目录全新。

## 4. 不做

- 不加会议、通知、报表等第二场景包。
- 不安装 Stirling-PDF、ffmpeg、faster-whisper 等外部工具。
- 不把 Uptime Kuma、n8n、Docmost、NetBox 放进产品导航。
- 不扩 AI 能力，不给桌面端新增 AI。
- 不做云同步、账号、多人实时协作。
- 不为“看起来完整”加假按钮、假统计、假入口。
- 不用功能数量宣称 v1.0。

## 5. 完成定义

阶段 A 完成，不是“清单写完了”，而是同时满足：

- 新用户 3 分钟完成首条归档。
- 所有空态有下一步，所有错误有恢复路径。
- 网页与桌面「更多」入口一致，权限一致。
- 性能有数，安装包可复现，文档无过期口径。
- 回归全过，线上与本地一致。

一句话：**让材料包安静地达到可交付，不靠新增功能。**
