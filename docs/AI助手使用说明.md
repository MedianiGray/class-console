# AI 助手使用说明（网页版 v0.27.0；附桌面分类建议）

入口有三个，按场景选：

1. **顶栏「✦ AI 副驾」**：任何页面都能点，右栏滑出建议面板；适合临时问一句、写群提醒。
2. **材料详情里的「AI 建议」**：选中一条材料后，在右栏详情底部，四个按钮直接查缺项 / 写驳回原因 / 拟归档命名 / 写情况说明。
3. **更多 → 智能辅助 → AI 助手**：完整对话页，适合长对话、模型配置、上下文勾选和预览。

定位：围绕材料整理主流程给建议和草稿，不替人做决定，不改台账、不发消息、不自动归档。

---

## 零点五、AI 副驾怎么用

- 顶栏点「✦ AI 副驾」，右栏打开，不切页；当前在哪个视图，它就读哪个视图的只读上下文。
- 工作台上下文给三个快捷：**先处理什么 / 写群提醒 / 列缺项**。
- 材料上下文给四个快捷：**查缺项 / 驳回原因草稿 / 归档命名建议 / 写情况说明**；打开时会带上当前材料的编号、名称、类别、提交人、状态、附件与说明。
- 生成结果只落在副驾面板里，不写进台账；你核对后仍需自己点归档 / 驳回 / 发消息。
- 每次生成单独记一条「AI 建议」日志，源标为「本地模型」或「API」，不混进材料的业务流转。
- 默认走本地模型；首次运行会下载权重。想换 API 或改上下文勾选，点面板底部「完整助手 / 模型配置」跳到完整页。

---

## 一、两种通道怎么选

| 通道 | 算力在哪 | 数据是否出设备 | 适合 |
|---|---|---|---|
| 本地模型 | 当前浏览器 / 本机 GPU | 不出设备 | 材料含姓名、学号等，或想离线用 |
| DeepSeek API | DeepSeek 云端 | 会离开设备 | 机器较弱、想要更好的表达质量 |

浏览器要求：Chrome / Edge，且 `navigator.gpu` 可用。没有 WebGPU 时只能走 API。

---

## 二、本地模型

1. 选模型：Qwen2.5 0.5B（低配）、Qwen2.5 1.5B（推荐）、DeepSeek R1 蒸馏 7B（更吃显存）。
2. 点「加载模型」。首次会下载权重并写入浏览器缓存；之后重新打开会快很多。
3. 状态显示「本地模型已就绪」后，直接输入问题或点快捷指令。

现实预期：

- 首次加载 0.5B 约 290MB，网络一般时要几分钟；期间进度会停在某个百分比，不代表卡死。
- 加载后断网仍可对话；对话记录只在本页内存，刷新即清空。
- 0.5B 能读台账并回答数量类问题，但长文写作和复杂推理明显弱于 1.5B / 7B。
- 手机端能跑但慢，电脑独显体验最好。
- 权重走 `hf-mirror.com`，运行库走 jsDelivr；两者都是国内可达链路。

## 三、API 通道

填写三项：

- Key：只存在当前页面内存，不写 `localStorage`，刷新后需重填。
- 模型名：默认 `deepseek-flash`。
- 接口地址：默认 `https://api.deepseek.com`，代码会自动补 `/chat/completions`；也可填完整的 OpenAI 兼容地址。

已实测：从 GitHub Pages 页面直接请求 DeepSeek 接口可以到达服务端；用无效 Key 返回 401。也就是说浏览器跨域不是硬阻断，真正能否生成取决于 Key 是否有效、账户是否有额度。

注意：

- API 模式会把勾选的台账、名单、任务和问题一起发到填写的接口；含敏感信息时改用本地模型。
- Key 会出现在浏览器网络请求里，公共电脑上不要使用。
- 如果接口服务端要求额外请求头或不允许浏览器直连，需要自建一个极简代理；当前版本不内置代理。

## 四、上下文与快捷指令

右侧「给它什么上下文」可勾选：

- 当前材料台账：总数、状态、类别、待审示例、已驳回原因。
- 名单核对：应交、已交、未交（仅管理岗可见）。
- 任务跟踪：截止、临期、逾期（仅管理岗可见）。

申请人视角只读取本人材料。点「预览将发送的上下文」可以先看实际会发出去的内容。

五组快捷指令：

1. 拆任务：目录、清单、分工、时间。
2. 列缺项 + 催交：用当前台账与名单。
3. 做核对清单：按类别、状态、佐证。
4. 写情况说明：事实、缺口、下一步。
5. 评优示例骨架：只作示例，可替换。

---

## 五、边界

- AI 输出只作草稿，发出前自己核对。
- 不会自动提交、审核、归档、发消息或联系任何人。
- 不生成身份证号、银行卡号、住址等敏感信息。
- 本地模型的效果受设备显存和模型尺寸限制，不承诺达到云端大模型水平。

## 六、桌面端 AI 分类建议（v0.26 新增）

桌面端只做**分类建议**，不进对话、不搬 WebGPU，默认关闭。

- **入口**：有 `docs:collect` 权限的角色，在「更多功能 → AI 建议」打开面板；收集视图里也有「AI 分类建议」按钮，只分析已勾选且未登记的文件。
- **默认行为**：没配 Key 时走本地关键词规则，按文件名把材料归到团务 / 奖助 / 学分 / 宣传 / 班级事务；结果带置信度与依据。
- **配置**：设置页「AI 建议（API-only）」填 OpenAI 兼容地址、模型、超时与 API Key；保存后状态行变「API 已启用」。默认地址是 SiliconFlow，默认模型 `Qwen/Qwen2.5-7B-Instruct`，可按实际供应商改。
- **发送范围**：只发文件名和允许类别列表，不读正文、不上传附件；单次最多 40 个文件。
- **回填**：面板可复制清单，或点「采用建议」把类别写回收集表的「入账类别」列；入账前仍可逐行改，采用不等于入账。
- **失败回退**：未配置、网络不可达、401 / 403 鉴权失败、429 限流或额度不足、5xx、超时、回包缺字段、内容不是 JSON、类别越界，都会回到本地规则，并在依据里写原因；不会带出 Key 或服务端原文。
- **存储与边界**：Key 只存本机 `%APPDATA%\ClassConsole\settings.json` 的 `ai` 段，不随清单复制、不写操作日志；AI 不改台账、不自动归档、不发消息。

## 七、常见问题

| 现象 | 处理 |
|---|---|
| `Failed to fetch` | 先确认 `hf-mirror.com` 与 jsDelivr 可访问；公司 / 学校网络可能拦截，换网络重试 |
| 没有 WebGPU / 适配器为空 | 换 Chrome / Edge，更新显卡驱动，或切 API 模式 |
| 首次加载很慢 | 正常，权重只下一次；保持页面打开，不要反复刷新 |
| 加载到某个百分比不动 | 看状态行是否仍有秒数在走；长时间无变化再刷新重试 |
| API 返回 401 | Key 无效或过期，重新生成 |
| API 返回 402 / 429 | 账户余额不足或触发限流，按服务商提示处理 |
| 回复很短或答非所问 | 换 1.5B，或把问题写具体；0.5B 不适合复杂任务 |
