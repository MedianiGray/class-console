# AI 助手使用说明（网页版 v0.20.1）

入口：网页版左侧「更多 → 更多功能 → AI 助手」。
定位：围绕材料整理主流程给建议和草稿，不替人做决定，不改台账、不发消息、不自动归档。

---

## 一、两种通道怎么选

| 通道 | 算力在哪 | 数据是否出设备 | 适合 |
|---|---|---|---|
| 本地模型 | 当前浏览器 / 本机 GPU | 不出设备 | 材料含姓名、学号等，或想离线用 |
| DeepSeek API | DeepSeek 云端 | 会离开设备 | 机器较弱、想要更好的表达质量 |

浏览器要求：Chrome / Edge，且 `navigator.gpu` 可用。没有 WebGPU 时只能走 API。

---

## 二、本地模型

1. 选模型：Qwen2.5 0.5B（低配）、Qwen2.5 1.5B（推荐）、DeepSeek R1 蒸馏 7B（更吃显存）。
2. 点「加载模型」。首次会下载权重并写入浏览器缓存；之后重新打开会快很多。
3. 状态显示「本地模型已就绪」后，直接输入问题或点快捷指令。

现实预期：

- 首次加载 0.5B 约 290MB，网络一般时要几分钟；期间进度会停在某个百分比，不代表卡死。
- 加载后断网仍可对话；对话记录只在本页内存，刷新即清空。
- 0.5B 能读台账并回答数量类问题，但长文写作和复杂推理明显弱于 1.5B / 7B。
- 手机端能跑但慢，电脑独显体验最好。
- 权重走 `hf-mirror.com`，运行库走 jsDelivr；两者都是国内可达链路。

---

## 三、API 通道

填写三项：

- Key：只存在当前页面内存，不写 `localStorage`，刷新后需重填。
- 模型名：默认 `deepseek-flash`。
- 接口地址：默认 `https://api.deepseek.com`，代码会自动补 `/chat/completions`；也可填完整的 OpenAI 兼容地址。

已实测：从 GitHub Pages 页面直接请求 DeepSeek 接口可以到达服务端；用无效 Key 返回 401。也就是说浏览器跨域不是硬阻断，真正能否生成取决于 Key 是否有效、账户是否有额度。

注意：

- API 模式会把勾选的台账、名单、任务和问题一起发到填写的接口；含敏感信息时改用本地模型。
- Key 会出现在浏览器网络请求里，公共电脑上不要使用。
- 如果接口服务端要求额外请求头或不允许浏览器直连，需要自建一个极简代理；当前版本不内置代理。

## 四、上下文与快捷指令

右侧「给它什么上下文」可勾选：

- 当前材料台账：总数、状态、类别、待审示例、已驳回原因。
- 名单核对：应交、已交、未交（仅管理岗可见）。
- 任务跟踪：截止、临期、逾期（仅管理岗可见）。

申请人视角只读取本人材料。点「预览将发送的上下文」可以先看实际会发出去的内容。

五组快捷指令：

1. 拆任务：目录、清单、分工、时间。
2. 列缺项 + 催交：用当前台账与名单。
3. 做核对清单：按类别、状态、佐证。
4. 写情况说明：事实、缺口、下一步。
5. 评优示例骨架：只作示例，可替换。

---

## 五、边界

- AI 输出只作草稿，发出前自己核对。
- 不会自动提交、审核、归档、发消息或联系任何人。
- 不生成身份证号、银行卡号、住址等敏感信息。
- 本地模型的效果受设备显存和模型尺寸限制，不承诺达到云端大模型水平。

---

## 六、常见问题

| 现象 | 处理 |
|---|---|
| `Failed to fetch` | 先确认 `hf-mirror.com` 与 jsDelivr 可访问；公司 / 学校网络可能拦截，换网络重试 |
| 没有 WebGPU / 适配器为空 | 换 Chrome / Edge，更新显卡驱动，或切 API 模式 |
| 首次加载很慢 | 正常，权重只下一次；保持页面打开，不要反复刷新 |
| 加载到某个百分比不动 | 看状态行是否仍有秒数在走；长时间无变化再刷新重试 |
| API 返回 401 | Key 无效或过期，重新生成 |
| API 返回 402 / 429 | 账户余额不足或触发限流，按服务商提示处理 |
| 回复很短或答非所问 | 换 1.5B，或把问题写具体；0.5B 不适合复杂任务 |
