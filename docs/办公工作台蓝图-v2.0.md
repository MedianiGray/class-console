# 办公工作台蓝图 v2.0（简洁版）

> **根本**：为解决所有办公问题，提供当前条件下能做到的极限协助。
>
> **形态**：一个入口接住问题，一个事项推到交付，一个下一步告诉人。
>
> **约束**：简洁而好用。不是功能多，而是每一步都少。
>
> 这份是目标态，不是当前版本说明。class-console 是它在“班级材料”上的第一个垂直实现。

## 0. 一页速览

- **一个入口**：收件 / 新建事项。任何办公问题都从这里开始。
- **一个对象**：事项。材料、会议、通知、报表、档案、交接，都是事项的不同形态。
- **一条主链**：起事 → 定事 → 办事 → 成事 → 了事。
- **一个主动作**：每屏只给一个实心按钮，其余是文字链、Ghost 或图标。
- **四级协助**：看见 → 建议 → 一键 → 规则。默认只走到“建议”，高级能力逐级展开。
- **六个场景**：材料收审、通知统计、会议活动、报表交差、档案整理、换届交接。
- **三个不做**：不做工具市场、不做应用启动器、不做替代人拍板的系统。

## 1. 根本与边界

### 1.1 什么叫“所有办公问题”

不是替所有职业做专业判断，而是接住用户实际会遇到的办公需求：

| 类型 | 典型问题 | 最终产出 |
| --- | --- | --- |
| 材料型 | 收材料、审材料、归档、备查 | 一套有位置、有状态、有证据的材料 |
| 会议型 | 开会、通知、签到、纪要、待办 | 一场有结论、有分工、有跟进的会 |
| 信息型 | 发通知、收回执、做统计、对齐口径 | 一份能直接发出去的文本或数字 |
| 报表型 | 周报、月报、汇总、评比、检查 | 一份能交差的报表或证据包 |
| 档案型 | 命名、归类、去重、检索、缺失反查 | 一个脱离软件也能看懂的档案库 |
| 交接型 | 换届、离职、学期末、项目结束 | 一个新人十分钟能接手的包 |

办公问题可以很多，入口不能很多。场景在“事项”里切换，不在侧栏里膨胀。

### 1.2 什么叫“极限协助”

把可标准化的部分尽量做到头，把必须由人判断的部分交得清楚。

| 用户卡点 | 系统该做 | 默认呈现 |
| --- | --- | --- |
| 不知道有什么要办 | 聚合待办、临期、异常 | 今日 |
| 知道要办但不会 | 给模板、示例、草稿、检查清单 | 建议 |
| 会做但重复 | 批量预填、批量整理、一键生成 | 预览后执行 |
| 规则明确且稳定 | 自动执行，逐条留日志，可回滚 | 自动化 |
| 出错了 | 说清原因、影响范围、恢复路径 | 异常卡 |

四级协助对应四种权限：

- **L0 看见**：只聚合、只提示，不动数据。
- **L1 建议**：给识别结果、草稿、目标路径，等人确认。默认级别。
- **L2 一键**：先 dry-run 预览，再整批执行，可撤销。
- **L3 规则**：满足条件自动执行，逐条留痕，可回滚，逐条开启。

### 1.3 协助不包办

- 价值判断、责任归属、关系协调、例外决策，归人。
- 官方口径、正式审批、对外发布，走真人或官方渠道。
- 工具不替人评价人，只描述事和材料。
- 做不到的能力，明确标“只读 / 本机 / 需安装 / 外部入口”，不放假按钮。

## 2. 主链

### 2.1 底层链

**信息 → 判断 → 行动 → 结果 → 交代**

办公的价值不在“处理文件”，而在把信息变成判断，把判断变成行动，把行动变成结果，把结果变成可交代的记录。

### 2.2 事项链

**起事 → 定事 → 办事 → 成事 → 了事**

| 阶段 | 要回答的问题 | 系统给什么 |
| --- | --- | --- |
| 起事 | 这是什么、从哪来、急不急 | 收件箱、来源、关联对象 |
| 定事 | 目标、对象、截止、产出是什么 | 事项卡、模板、默认下一步 |
| 办事 | 找什么依据、谁配合、怎么做 | 检索、草稿、任务、催办、计算 |
| 成事 | 口径对不对、能不能交 | 校验、预览、定稿、交付 |
| 了事 | 放哪、怎么查、怎么交接 | 归档、索引、日志、交接包 |

### 2.3 系统最小闭环

**收件 → 事项 → 对象 / 产出 → 日志 / 撤销 → 归档 / 交接**

任何一条办公事项，至少要做到：

- 进得来：有入口，不丢。
- 说得出：有标题、对象、截止、产出。
- 推得动：知道下一步，能找人、找依据。
- 交得出：有可交付物。
- 查得到：事后能按人、事、时间、对象找回。
- 接得住：换人、换学期、换项目能交接。

## 3. 一件事的最小模型

| 字段 | 含义 |
| --- | --- |
| 标题 | 人话，说明要办什么 |
| 场景 | 材料 / 会议 / 通知 / 报表 / 档案 / 交接 |
| 状态 | 收件 / 进行 / 待确认 / 待审 / 已完成 / 已归档 |
| 负责人 | 谁推进 |
| 截止 | 什么时候要 |
| 对象 | 文件、人、表格、会议、消息 |
| 产出 | 文档、表格、纪要、通知稿、证据包 |
| 下一步 | 当前唯一推荐动作 |
| 留痕 | 谁在什么时候做了什么 |

没有“下一步”的事项，就是死事项。工作台的第一职责，是让每件事始终有一个明确的下一步。

## 4. 界面：一屏五区

```
顶栏：搜索 / 命令 · 提醒 · 身份 · 设置
侧栏：今日 · 事项 · 资产 · 自动化 · 更多
主区：当前一件事（列表 / 看板 / 日历 / 文件）
上下文栏：详情 · 预览 · 产出 · 留痕 · 下一步
状态栏：本地 · 数据规模 · 索引状态 · 后台任务
```

### 4.1 侧栏只留四项半

- **今日**：待我处理、临期、异常、未交。
- **事项**：所有场景的事，用筛选切换，不按场景加导航。
- **资产**：文件、表格、档案、索引。
- **自动化**：规则、队列、运行记录。
- **更多**：低频工具、设置、实验能力。默认收起，不占主视线。

材料、会议、通知、报表、交接，都进“事项”的筛选，不各占一个侧栏入口。

### 4.2 三个一

1. **一个入口**：任何事从收件或新建开始。
2. **一个焦点**：一屏只处理一类对象、一个当前事项。
3. **一个主动作**：每屏只有一个实心按钮，写清“下一步做什么”。

### 4.3 七条硬规则

1. **三步内开始**：任何事项 ≤3 步进入执行。
2. **两动作找到**：任何对象、文件、人 ≤2 个动作找到。
3. **能就地不弹窗**：详情、预览、备注、批量确认在右栏或底部条。
4. **折叠不删除**：低频进「更多」，原能力保留。
5. **默认只显示下一步**：高级选项渐进披露，不一上来铺满。
6. **批量先预览**：先看将改什么，再执行，可整批撤销。
7. **状态就地变**：审核、勾选、完成后只更新那一行，不整表重建。

## 5. 四层架构

```
入口层：收件 · 搜索/命令 · 事项 · 资产 · 自动化 · 更多
场景层：材料收审 · 通知统计 · 会议活动 · 报表交差 · 档案整理 · 换届交接
能力层：收 · 识 · 整 · 转 · 算 · 查 · 写 · 发 · 排 · 审 · 存 · 交
底座层：对象模型 · 文件库 · 索引 · 权限 · 日志 · 版本 · 备份 · 撤销
```

### 5.1 能力层十二个原子动作

| 能力 | 做什么 | 典型场景 |
| --- | --- | --- |
| 收 | 文件、表单、消息进来 | 收件、提交 |
| 识 | 提字段、提正文、提要点 | 材料识别、会议转写 |
| 整 | 分类、命名、去重、归位 | 材料整理、档案整理 |
| 转 | 改格式、合并、拆分、压缩 | PDF、音视频、表格 |
| 算 | 汇总、统计、校验 | 报表、名单、完成率 |
| 查 | 按人、事、时间、对象检索 | 全局搜索 |
| 写 | 按模板出草稿 | 通知、纪要、周报 |
| 发 | 生成可粘贴文本、回执入口 | 催交、通知 |
| 排 | 截止、提醒、周期任务 | 日程、任务 |
| 审 | 通过、驳回、待补、异常 | 材料审核 |
| 存 | 归档、索引、证据包 | 交差、备查 |
| 交 | 打包、导入、权限转移 | 换届、项目交接 |

### 5.2 场景层不重写能力

新增一个场景包，只加配置和少量适配：

- 状态机
- 表单字段
- 默认视图
- 需要的原子能力
- 产出模板
- 角色与权限

验收：**不改主界面，只加配置，就能跑通“收件 → 处理 → 产出 → 归位”。**

## 6. 场景包顺序

| 顺序 | 场景包 | 为什么现在/以后做 | 依赖 |
| --- | --- | --- | --- |
| S1 | 材料收审 | 当前唯一成熟垂直链，先收口到 v1.0 | 已有 |
| S2 | 通知统计 | 高频、低复杂度，最容易验证“第二包不改主界面” | 名单、话术、回执 |
| S3 | 会议活动 | 会议多、纪要散，收益直接 | 转写、任务、纪要模板 |
| S4 | 报表交差 | 周报、月报、评比、检查的出口 | 汇总、模板、证据包 |
| S5 | 换届交接 | 学期末/换届刚需，决定公共记忆能否留下 | 打包、导入、权限 |
| 横向 | 档案整理 | 不单列场景包，作为“资产”层通用能力 | 文件库、索引 |

## 7. 路线图

### 阶段 A · 材料包收口（现在）

- 完成 v1.0 静默版：首次引导、空态/错误态、性能、安装包。
- 不安装外部增强包，不新增侧栏工具位。
- 验收：新用户 3 分钟完成一次提交 → 审核 → 归档。

### 阶段 B · 抽底座

- 把材料包里的对象、收件、搜索、日志、撤销抽成通用能力。
- 事项模型落地，材料只是第一个场景。
- 验收：新增“通知统计”包不改主界面。

### 阶段 C · 第二个包

- 通知统计：名单、话术、回执、统计、导出。
- 验收：同一套搜索、权限、日志、归档可复用。

### 阶段 D · 会议活动

- 议题、参会、材料、纪要、待办。
- 转写、音视频只作为能力层，不做独立工具广场。
- 验收：一场会从通知到待办闭环。

### 阶段 E · 报表与交接

- 周报/月报、证据包、届别交接包。
- 验收：包脱离软件可读，新人十分钟接手。

## 8. 验收尺

1. 任何办公问题 ≤3 步进入执行。
2. 单件事上下文切换 ≤1 次。
3. 任意对象、文件、人 ≤2 个动作找到。
4. 一屏只有一个视觉重点、一个实心主按钮。
5. 全流程无弹窗链；破坏性动作才确认。
6. 批量操作可整批撤销，零原件丢失。
7. 关掉重开，未完成的事仍在原地。
8. 新增场景包 ≤1 天配置接入，不重做界面。

## 9. 不做

- 不做插件市场、工具宫格、应用启动器。
- 不做云同步、账号体系、多人实时协作、多租户。
- 不做生成式 AI 代写代判；AI 只出草稿，关键动作人工确认。
- 不做独立聊天窗口、移动原生 App。
- 不把 Uptime Kuma、n8n、Docmost、NetBox 这类外部服务塞进产品导航。
- 不把「更多」做成第二个侧栏；它只是低频收口。
- 不对未实现能力放假按钮。

## 10. 与 class-console 的关系

class-console 是这套蓝图的**第一个垂直场景包**，不是全部。

它的系统主链仍是：

**提交 → 待审核 → 归档/驳回 → 留痕 → 备份/交接**

这条链要在这个场景里做到极限，但不能拿它代表所有办公。下一步不是把 class-console 做得更大，而是把它的底座抽出来，让第二个场景包复用同一套对象、搜索、权限、日志、撤销与归档。

一句话收束：

**入口只有一个，事项只有一条链，界面只给一个下一步；协助尽量到极限，判断始终留给人。**
