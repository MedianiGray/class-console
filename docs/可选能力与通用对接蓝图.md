# 可选能力与通用对接蓝图

> 本篇是《工作台蓝图.md》的专篇补充：专门规划"文件监听、后台轮询、网络请求、外部客户端 / 网页对接"这类可选能力——**默认不开启，由用户主动启用**；对接代码做成**通用可配置**，不绑死某一家平台或网站。
> 平台与 AI 的落地步骤见《接入规划.md》；版本与稳定性机制见《迭代与稳定性方案.md》。
> 当前版本：v0.2.0，本篇所列对接能力均为规划，尚未在代码中实现。

## 一、实际需求整理

### 1.1 业务需求（这个工作台要帮老师做什么）

| 编号 | 需求 | 归属 |
|---|---|---|
| B1 | 材料收集录入，名称 / 姓名 / 学号 / 类别 / 说明 / 附件名 | 核心本地，已实现 |
| B2 | 台账分类、搜索、状态筛选，查看详情与留痕 | 核心本地，已实现 |
| B3 | 审核流转：归档 / 驳回，二次确认，写入状态与日志 | 核心本地，已实现 |
| B4 | 操作留痕：谁、何时、什么角色、做了什么、对哪份材料，可追溯可导出 | 核心本地，已实现 |
| B5 | 看板概览：待办置顶、类别分布、近期动态 | 核心本地，已实现 |
| B6 | 人员名单与缺交核对、材料任务与截止跟踪 | 本地待补 |
| B7 | 附件真实落盘、Excel / CSV 导入导出、审核备注 | 本地待补 |
| B8 | 从本机文件夹收集材料：识别目录里新增 / 减少 / 变更的文件及相关信息 | 可选本地能力，默认关 |
| B9 | 从外部客户端 / 平台读取或回写材料与状态（WPS、飞书、钉钉等） | 外部对接，默认关 |
| B10 | 识别网页链接里的数据（按链接抓取并解析成材料记录） | 外部对接，默认关 |
| B11 | AI 辅助：分类建议、齐全度检查、重复识别、文案草稿、检索问答 | 外部能力，默认关 |

### 1.2 非功能需求

- **离线优先**：不启用任何外部能力时，程序纯本地运行，不联网、不监听外部目录、不读网页。
- **可选可关**：监听、轮询、网络请求、外部对接都是独立开关，默认关闭；用户可在设置里逐项启用或关闭。
- **通用不绑死**：对接层抽象成可替换的适配器，新增一个平台 / 网站 / 客户端只加适配器和配置，不改界面与仓库核心。
- **可回退**：任何外部能力失败或关闭后，回退纯本地，不卡死、不丢数据。
- **隐私最小化**：外部读取 / 上传前明示范围；敏感信息可设为不出本机；凭据本机安全存储。
- **留痕一致**：无论数据来自本机录入还是外部对接，入库与动作都走同一套日志留痕，记录来源。

## 二、能力分级与默认策略

### 2.1 三级划分

| 级别 | 含义 | 是否联网 | 默认状态 | 举例 |
|---|---|---|---|---|
| L1 核心本地能力 | 工作台主流程，必须可用 | 否 | 始终开启，不可关闭 | 台账、提交、归档、驳回、日志、备份、看板 |
| L2 可选本地能力 | 增强本地效率，不离开本机 | 否 | **默认关闭**，设置中可开 | 文件夹扫描 / 监听、本地文件批量导入、定时本地备份 |
| L3 外部对接能力 | 访问本机之外的数据或服务 | 是 | **默认关闭**，首次使用前询问确认 | 平台 API 对接、网页链接抓取、AI 调用、消息通知 |

### 2.2 默认状态表（规划）

| 能力 | 默认 | 启用入口 | 联网 | 关闭 / 回退方式 |
|---|---|---|---|---|
| 文件夹扫描清单对比 | 关 | 设置 → 本地能力 | 否 | 关闭后停止扫描，本地数据保留 |
| 文件夹变更监听 | 关 | 设置 → 本地能力 | 否 | 关闭后释放监听句柄 |
| 后台轮询 | 关 | 设置 → 本地能力 / 对接 | 否（本地）或 是（远程） | 关闭定时器，不再自动拉取 |
| 平台 API 对接 | 关 | 设置 → 外部对接 | 是 | 断开连接，切回本地仓库 |
| 网页链接数据识别 | 关 | 提交 / 台账内按需触发 | 是 | 不发起请求，仅保留手动录入 |
| AI 辅助 | 关 | 设置 → AI | 是 | 回退本地规则，主流程不受影响 |

### 2.3 启动询问机制

1. **首次启动**：出现一次"可选能力"引导，逐项说明用途、是否联网、数据流向；**全部默认不勾选**，用户逐项确认后才启用。
2. **记住选择**：已确认的开关状态写入本机配置，之后不再每次询问；设置页可随时改。
3. **未启用不加载**：开关关闭时，对应模块代码不初始化、不创建监听、不发起网络请求；状态栏显示"本地模式"。
4. **启用前明示**：L3 能力启用前弹窗提示数据会离开本机、上传哪些字段、凭据存哪里，用户确认后才保存配置。

## 三、通用对接层架构

### 3.1 设计原则

- **适配器模式**：对接层定义统一接口，每一种来源（文件夹、文件、平台、网页、AI）实现一个适配器；上层只认统一接口，不关心具体对方是谁。
- **配置驱动**：地址、凭据、字段映射、解析规则、脱敏开关都写在配置文件里，不硬编码进程序。
- **统一入库**：适配器把外部数据转成统一中间结构（dict），再走现有仓库方法入库与留痕，界面流程不变。
- **独立可替换**：新增来源 = 新增一个适配器 + 一段配置；移除来源 = 关闭开关，不影响核心流程。

### 3.2 连接器统一接口（规划）

```
Connector（抽象基类）
  name            连接器标识
  enabled         是否启用（读配置）
  configure(cfg) 载入配置
  test()          连通性自检，返回是否可用与提示
  pull()          拉取外部数据，转成统一中间结构
  push(record)    （可选）回写状态 / 记录到外部
  health()        健康状态：本地 / 已连接 / 离线 / 失败
  close()         释放句柄、连接、定时器
```

### 3.3 适配器分类

| 适配器 | 对接对象 | 输入（可配置） | 输出 | 级别 |
|---|---|---|---|---|
| FolderConnector | 本机磁盘文件夹 | 目录路径、文件类型过滤、是否递归 | 文件清单：文件名、大小、修改时间、类型、路径；变更对比得出新增 / 减少 / 变更 | L2 |
| FileImportConnector | 导出的本地文件 | 文件路径、格式（CSV / Excel / JSON）、列名映射 | 材料记录列表 | L2 |
| PlatformApiConnector | 协作平台（WPS / 飞书 / 钉钉等） | 平台类型、接口地址、应用凭据、表格 / 文档标识、字段映射 | 材料记录、状态、日志；可回写状态 | L3 |
| WebLinkConnector | 网页链接 | URL、解析规则（选择器 / 字段映射）、是否需要登录态 | 从页面识别出的结构化记录 | L3 |
| AiConnector | 大模型服务 | 模型地址、密钥、超时、可用字段范围、降级开关 | 建议结果（分类 / 摘要 / 话术），人工确认后生效 | L3 |

### 3.4 配置文件（规划：`config.json`）

```
{
  "local": {
    "folder_watch": { "enabled": false, "paths": [], "file_types": [] },
    "auto_backup": { "enabled": false, "interval": "daily" }
  },
  "connectors": {
    "platform": { "enabled": false, "type": "", "endpoint": "",
                  "credentials": {}, "field_map": {}, "sync": "manual" },
    "web": { "enabled": false, "rules": [] },
    "ai": { "enabled": false, "endpoint": "", "model": "", "key": "",
            "allow_fields": [], "fallback": "local" }
  },
  "privacy": { "mask_sid": true, "allow_upload": false }
}
```

- 凭据只存本机配置目录，不写进源码、不打进公开包。
- 字段映射可配：外部列名 ↔ 内部字段（name / who / sid / cat / note / file）。

### 3.5 数据流与留痕

```
外部来源 ──► 适配器 pull() ──► 统一中间结构(dict)
                                   │  字段映射 / 脱敏 / 校验
                                   ▼
                            仓库层 add_doc / add_log
                                   │
                                   ▼
                        本机 SQLite + 日志（src 记录来源连接器）
```

- 外部写入的材料，日志 `src` 标注来源（如"WPS 表格""网页链接""文件夹导入"），与本机录入区分。
- 回写外部（push）属可选动作，默认只拉不写；开放写入前单独确认。

## 四、与现有代码的衔接点

| 要做的事 | 改动位置 / 新增文件 | 说明 |
|---|---|---|
| 能力开关与配置 | 新增 `config.py` 读写 `config.json`；主窗口加"设置 / 对接"入口 | 未启用不初始化对应连接器 |
| 连接器抽象 | 新增 `connectors/` 目录与基类 | 统一接口，适配器各自实现 |
| 文件夹扫描 / 监听 | `connectors/folder.py` | 标准库 `os` / `pathlib` 起步；监听按需引入 |
| 文件导入 | `connectors/file_import.py` | CSV 标准库起步，Excel 按需引 openpyxl |
| 平台对接 | `connectors/platform_*.py` + `cloud_client.py` | 标准库 urllib 起步，需要时再引 requests |
| 网页识别 | `connectors/web_link.py` | 通用 HTTP 抓取 + 可配解析规则 |
| AI 调用 | `ai_service.py` | 与仓库层解耦，支持降级回退 |
| 仓库替换 | `database.py` 的 `build_repository` 与 `DATA_BACKEND` | 远程仓库实现同契约方法即可切换 |

> 现有仓库方法契约保持不变：`list_docs / add_doc / archive_doc / reject_doc / list_logs / add_log / stats / backup / restore`。

## 五、分阶段制作安排

### 阶段一 · 本地打磨（不联网，先做扎实）

1. 人员名单与缺交核对、材料任务与截止跟踪。
2. 附件真实落盘；CSV / Excel 导入导出；审核备注；校验增强。
3. **配置骨架与开关框架**：先落地 `config.json` 读写和设置页，只挂 L2 本地连接器；L3 开关占位、不可用。
4. 文件夹扫描清单对比（L2，默认关）：选目录 → 列出文件及属性 → 对比前后清单，标出新增 / 减少 / 变更。

### 阶段二 · 通用对接（外部能力，逐项启用，默认关）

1. 落地连接器抽象基类与注册机制。
2. 文件导入适配器（本地导出文件批量入库）。
3. 文件夹变更监听适配器（在扫描基础上加监听，可选）。
4. 选学校在用的一个平台，做只读连接器试点；字段映射确认后再开放回写。
5. 网页链接连接器：先支持规则明确的页面，解析结果人工确认后入库。
6. 后台轮询：仅在对应连接器启用后启动定时器；可设间隔，失败重试与离线回退。

### 阶段三 · AI 辅助（网页版已落地原型）

- 网页版已先落地「AI 助手」：本地 WebGPU 模型与 OpenAI 兼容 API 双通道，可带入台账 / 名单 / 任务上下文，提供拆任务、催交、核对、情况说明等草稿；只给建议，不改台账、不发消息、不自动归档。
- 桌面端 AiConnector 仍按原计划独立成模块，从分类建议切入；结果入日志，关键动作人工确认；未配置或不可用时回退本地规则。

### 阶段四 · 远期

- 多人实时协作、手机端、学期归档包、审计导出；多端需后端与跨端架构另立项目评估。

## 六、安全与合规边界

- **默认离线**：出厂配置所有外部能力为关；不启用就不联网、不监听、不读外部目录。
- **明示再授权**：L3 启用前说明数据流向、上传字段、凭据位置；可随时关闭并清除本机凭据。
- **最小化与脱敏**：学号、姓名等按需要使用；可配置脱敏；敏感材料保留"不出本机"。
- **失败回退**：连接器异常不阻断本地提交、审核、查看；外部数据拉取失败先留本地缓存，联网后再补。
- **可导出可迁移**：所有入库数据可导出，不被单一平台或网站锁死。

## 七、验收标准（可选能力相关）

1. 全新启动、未改配置时：不发起任何网络请求，不监听外部目录，状态栏显示本地模式。
2. 每个 L2 / L3 能力在设置里有独立开关，默认关闭；关闭后对应模块不初始化、不起定时器、不建连接。
3. 启用 L3 能力前有确认提示，写明数据流向与上传范围；凭据仅存本机配置目录。
4. 适配器拉取的数据经字段映射、校验、脱敏后入库；日志记录来源连接器。
5. 连接器连通性自检可用；失败时回退本地，主流程不崩、不丢数据。
6. 新增一个平台 / 网站来源，只新增适配器与配置项，不改界面层与仓库核心方法。

## 八、当前不承诺的边界

- 通用对接不等于"自动识别任意网站 / 任意客户端"：解析规则和字段映射需要按具体对象配置；目标站点有权限、登录态、反爬限制时无法绕过。
- 平台对接需对方开放 API 与相应授权；网页抓取需遵守目标站点规则与版权要求。
- 文件夹监听、后台轮询、网页识别与桌面端 AI 调用当前仍未实现；网页版 AI 已作为先行原型落地，不改变桌面端默认离线口径。
- 本蓝图是规划安排，具体实现以每轮自检通过的版本为准。
