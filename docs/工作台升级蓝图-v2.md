# 工作台升级蓝图 v2 · 对标成熟后台重做

> 本篇回答一个问题：对照业界成熟的管理后台 / 工作台标杆，我们现在这版差在哪、下一步按什么顺序把它做成一个真正好用的效率工具。
> 业务口径与数据模型沿用《工作台蓝图.md》；外部对接与 AI 的分级策略沿用《可选能力与通用对接蓝图.md》；本篇聚焦**信息架构、交互范式、表格能力、反馈体系与工程规范**。
> 状态：规划稿，未经确认不改动现有可运行版本。

## 一、先给结论

现在的版本把"提交 → 审核 → 归档 → 留痕"闭环跑通了，数据口径一致、可备份恢复，作为本地单机工具是合格的。但按成熟工作台的标准衡量，它目前更像"几张能填能看的表"，还不是一个能让学委/老师少点点击、快速定位问题、批量处理事务的操作台。

差距不在功能多少，而在四类基础能力：

1. **列表处理能力弱**：不能排序、不能分页、不能多选批量处理，数据一多就只能往下翻。
2. **筛选与检索不成体系**：搜索、下拉筛选是散的，没有已生效条件的清晰呈现，离开列表再回来条件就丢了。
3. **交互一致性和反馈不完整**：详情用弹窗打断流程，缺行内快捷操作、进度反馈、撤销和有引导的空状态。
4. **信息架构以数据对象为中心，而不是以"要处理的事"为中心**：首页没有把"我现在该先处理什么"顶到最前面。

## 二、参照的标杆与提炼的共识

调研参照：Ant Design Pro（中后台脚手架范式）、Bolder Apps 后台门户设计指南、ux-admin-portal 设计框架、墨刀 B 端数据表格实践，以及常见班级/教务台账产品（花名册关联、缺交追踪、催办、隐私互不可见）。

各来源收敛出的、与我们场景直接相关的共识：

- **结果导向的导航**：界面围绕"待处理事项"组织，而不是围绕数据表名罗列；首页先回答"什么变了、什么卡住、哪件事要我马上处理"。
- **高密度但易扫读的表格**：文本左对齐、数值右对齐，斑马纹或行分隔；列头可排序，默认按最常用顺序；分页而非无限滚动；行操作分层，高频直接点，低频收进菜单。
- **成体系的筛选**：搜索常驻顶部；多条件可叠加；已生效条件做成可移除的标签；显示匹配条数；零结果空态给下一步建议和"清除全部筛选"。
- **不离开列表的详情**：右侧抽屉或预览面板看详情、看留痕，返回时保留筛选和浏览位置；复杂编辑才进独立页面。
- **一致的 CRUD 节奏**：创建成功跳回列表或详情并给成功提示；简单字段行内改，复杂字段进侧栏；破坏性动作必须点名确认；可恢复优于永久删除。
- **批量操作有计数、有预览、有结果汇总**：选中后出现上下文操作栏；执行前确认影响范围；超过 2 秒给进度；部分失败逐条列出；完成后清空选择。
- **反馈与空态是产品的一部分**：每个动作都有即时反馈；错误信息说清发生了什么、数据是否保住、下一步点哪；空表不是白屏，而是带引导的说明。
- **权限先做前端适配**：按角色隐藏/禁用/只读/重定向；真正的权限强制必须在后端，前端只负责减少困惑。

## 四、重做后的信息架构

### 4.1 导航分组（侧边栏）

- **处理事务**：工作台概览、待审核队列、材料台账
- **收集录入**：提交材料、人员名单（待补）
- **追溯与备份**：操作日志、备份与恢复
- **系统**：设置（可选能力开关、偏好、数据）

导航项按使用频率排序；低频项收进分组，不与高频项抢位置。窄屏时导航折叠为图标轨或顶部横滑。

### 4.2 首页：待办优先的结果台

落地页一屏内回答三件事：

1. **现在该处理什么**：待审核队列置顶，按提交时间/类别排，带优先级色点和临期标记；每条可直接进入处理。
2. **最近发生了什么**：近期动态流（谁、何时、对哪份材料做了什么）。
3. **整体盘子**：总数、待审核、已归档、已驳回，外加类别分布；卡片支持点按下钻到对应台账筛选。

快捷操作固定在首页显眼位置：提交新材料、打开台账、导出备份。

### 4.3 各页面布局

- **台账页**：顶部常驻搜索 + 筛选区；条件标签行；工具栏右侧放视图保存、列显隐、密度切换；下方高密度表格；底部分页与条数统计。
- **提交页**：分区分组（基本信息、材料信息、附件）；字段标签与必填规则就近标注；底部保存/清空。
- **详情抽屉**：右侧滑出，左侧列表不丢失上下文；上部基本信息与状态，中部附件与说明，下部该材料留痕时间线；底部快捷操作（归档/驳回/查看记录）。
- **日志页**：筛选 + 表格；顶部备份导入导出入口。
- **设置页**：可选能力开关（沿用对接蓝图分级）、界面偏好、数据管理（导出/导入/清空）。

## 五、关键交互范式落地细则

### 5.1 表格

- 列头点击切换升/降序，箭头指示当前排序列；默认按提交时间倒序；排序态在翻页和进出详情后保持。
- 分页：每页 10/25/50 可选，显示"第 1–10 条，共 N 条"；提供跳页。
- 行密度三档：紧凑 32px、舒适 40px（默认）、宽松 48px；偏好本机记住。
- 文本列左对齐，学号/编号等编号列用等宽字体；表头与数据对齐方式一致。
- 首列（材料名称）和操作列在横向滚动时冻结；列多时给出"还有 N 列可横滑"提示，不静默裁掉数据。
- 移动端表格转为卡片列表，每条材料一张卡，保留关键字段和主操作。

### 5.2 筛选与检索

- 搜索框常驻，输入 2–3 字符或停顿 300ms 后出结果；显示匹配条数。
- 条件可叠加：状态、类别、时间范围、姓名/学号；已生效条件以标签形式挂在结果上方，标签上的 × 单项移除，另有"清除全部"。
- 常用筛选组合可保存为命名视图，下次一键调用；筛选状态写入本机，离开再回来不丢。
- 零结果空态：说明没有匹配材料，给出"放宽条件"或"清除全部筛选"的动作入口。

### 5.3 详情与编辑

- 列表行单击选中，双击或点"查看"打开右侧抽屉；抽屉内看全字段与留痕，关闭后回到列表原位置。
- 简单状态类操作（改状态、改备注）尽量在行内或抽屉内完成；多字段编辑进独立表单或侧栏。
- 表单逐字段校验，错误在字段下方就近提示；长表单暂存草稿，误关页面不丢；提交成功跳回列表并提示，新材料置顶可见。

### 5.4 批量操作

- 表头三态复选框：未选/全选本页/半选（跨页已选）；明确区分"选本页"与"选全部结果"。
- 选中后工具栏切换为上下文操作栏，显示已选数量；只显示对所选记录都有效的动作，混合不可处理时标出"X 条不可处理"。
- 执行前确认弹窗写明：动作类型、涉及条数、影响结果；高风险动作要求明确确认。
- 超过 2 秒的操作显示进度（处理 X / 共 Y）；结束后给结果汇总：成功几条、失败几条及失败原因；完成后清空选择。
- 提供限时撤销提示（5–10 秒）；删除优先走归档/回收站，保留恢复期，不做不可恢复的物理删除。

### 5.5 反馈与健壮性

- 每个动作给即时反馈：成功 toast、内联错误、加载态；常规状态切换先更新界面再落盘，失败回滚并提示。
- 后台重任务（批量导入、导出大文件）有可观测的进度入口，不卡住主界面。
- 错误信息不用系统码：说清发生了什么、数据是否保住、下一步点哪；网络/存储失败回退本地，不丢已录入内容。
- 空表、无搜索结果、无权限、加载中四种状态各有明确界面，不用白屏或空壳占位。

### 5.6 角色与权限（前端适配层）

- 权限按 `资源:动作` 描述（如 `docs:archive`、`docs:reject`、`logs:view`），界面元素映射到对应权限串。
- 四策略：无关功能隐藏、存在但禁用、只读可见、直接访问受保护页给说明页。
- 导航按权限过滤，空分组不显示；界面标注当前角色与可见范围。
- 说明：前端这套只做体验适配，真正的权限强制必须落在后端；单机版的视角切换仍是演示性质。

## 六、视觉与工程规范

### 6.1 设计 token

- 间距走 8px 网格；字号、行高、圆角、阴影成体系，不随手写值。
- 语义色分离：成功/警告/危险/中性分别对应文字色、底色、描边色，状态标签复用同一套。
- 预留明暗主题切换的变量层；当前先保证浅色一套完整可用。
- 所有可点控件有可见焦点环，支持 Tab 导航与回车触发；表单控件带无障碍标注。

### 6.2 工程分层

```
视图层  各页面/导航/抽屉/表格/表单，只负责呈现与交互
组件层  可复用表格、筛选栏、标签、状态徽章、空态、弹窗/抽屉、toast
仓库层  固定方法契约：listDocs / addDoc / archiveDoc / rejectDoc
                 listLogs / addLog / stats / backup / restore
对接层  连接器适配器，按对接蓝图分级，默认关闭、可替换
```

- 桌面 Python 端与网页端实现同一套仓库契约；界面各自实现，数据口径、状态枚举、角色称呼保持一致。
- 网页版从单文件逐步拆出组件与服务模块，避免后续功能堆在一个 HTML 里难以维护。
- 每轮改动跑固定回归自检；新问题用例固化进测试目录。

## 七、分阶段路线

### P0 · 现有闭环做到标杆标准（不新增业务）

目标：把已经能用的流程，在交互和列表能力上补到成熟工作台水平。

1. 表格：列排序、分页与每页条数、密度切换、冻结列、窄屏卡片化。
2. 筛选：条件标签、匹配计数、筛选态保持、搜索防抖。
3. 详情：弹窗改右侧抽屉，列表上下文保持。
4. 首页：待审核队列优先级置顶，卡片可下钻，补快捷操作。
5. 反馈：补空态引导、错误平静提示、动作后的明确反馈。

### P1 · 本地业务补全与规范

1. 人员名单：学号—姓名对照，提交时带出；缺交名单核对。
2. 材料任务与截止跟踪：应交/已交/未交状态，临期提示。
3. 附件真实落盘；CSV/Excel 导入导出；审核备注与驳回原因。
4. 表单草稿暂存；列显隐与偏好记忆。
5. 视觉 token 梳理、焦点环与键盘可达性检查。

### P2 · 外部对接与 AI（沿用对接蓝图）

- 连接器抽象与注册；本地文件批量导入；选一个在用平台做只读试点；网页链接解析；AI 辅助只出建议、关键动作人工确认。
- 所有外部能力默认关闭，首次启用前明示数据流向，可随时回退本地。

### P3 · 多人共享与多端（需另立评估）

- 多人各自提交、老师统一汇总可见；跨端一致。这需要后端服务、数据库、账号体系与托管部署，纯静态网页 + 本地缓存实现不了，确有需求时单独评估架构与成本。

## 八、验收标准（P0 完成口径）

1. 台账表格可按任意列排序，默认最新优先；分页显示总数与当前范围；密度可切换。
2. 搜索与叠加筛选即时出结果，已生效条件可单项移除或一键清空；离开列表再回来条件仍在。
3. 打开详情走右侧抽屉，关闭后回到列表原筛选位置与浏览位置。
4. 首页待审核队列置顶可直达处理；统计卡片可下钻到对应筛选台账。
5. 提交、归档、驳回、查看、备份导入导出全链路在桌面端与网页端口径一致；控制台无报错。
6. 空表、无结果、加载中、操作失败四类状态都有明确界面与下一步指引。
7. 回归自检通过；不引入未声明的联网行为，离线主流程完整可用。

## 九、边界与不承诺

- 本蓝图是产品与交互重做的规划，具体实现以每轮自检通过的版本为准。
- 单机本地版不保证多人实时一致；多人共享、跨端同步必须走后端方案。
- 附件当前仅记文件名，落盘与可打开属于 P1；外部平台、网页识别、AI 属 P2，默认不启用。
- 前端角色适配不等于安全权限；真正的身份分级控制依赖后端。
