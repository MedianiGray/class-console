# 班级材料操作台 · Class Console

> 面向班级学委 / 辅导员的**离线优先**材料工作台：把材料从提交、审核、归档到留痕的流程收拢在一个本地程序里闭环。
>
> 当前版本：**网页版 v0.22.0 · 桌面端 v0.22.0（兜底版）** ｜ 运行环境：Python 3 + Tkinter + Pillow（EXE 已内置）｜ 协议：MIT（占位，可更换）

## 一、项目简介

本项目为班级材料收集与归档场景设计，区别于只做链接跳转的导航页：它管理"材料进来 → 状态流转 → 归档留痕"的完整业务过程。

- **交付形态**：Windows 原生桌面程序（Tkinter 窗口），双击 exe 独立运行；不起本地服务、不依赖浏览器、不需要命令行窗口。
- **数据归属**：材料与操作日志保存在本机 SQLite，断网可用；网页版可使用浏览器本地模型或自填 API，桌面端 AI 入口仍在规划中。
- **设计原则**：离线优先、先本地后云端、可回退可迁移、隐私最小化、关键动作人工确认。

## 二、功能特性

### 已实现（本地闭环）

| 模块 | 能力 |
|---|---|
| 工作台看板 | 总数 / 待审核 / 已归档 / 已驳回统计卡片、类别分布、待审核置顶、近期动态 |
| 材料台账 | 编号列；按材料名 / 姓名 / 学号搜索，类别、类型与状态筛选，详情抽屉展示类型、模板专属栏目、编号与附件清单，单条材料留痕时间线（提交 / 归档 / 驳回 / 归位逐节点回放） |
| 文件室 | 归档目录树 + 文件列表 + 预览三栏；按台账与索引标记「台账有 / 仅索引 / 未登记」，可全库搜文件名；文本前 200 字、图片 / PDF Shell 缩略图；缺失文件反查可回台账或重新归位；文件拖入窗口即复制落位并登记为待审核，同名自动 `_v2` |
| 审计与证据 | 桌面端：索引、磁盘与台账三方完整性检查，可重建索引、重新归位缺失文件；按类别与日期导出 ZIP 证据包，内含材料清单、索引、日志、文件树、说明与 manifest，可选附带原始文件 |
| 网页本地版 | 单文件浏览器版与桌面端主体同频：分组侧栏、统一页头、提醒中心、材料模板字段配置、详情审批节点、真实多选与批量操作；台账列宽可拖拽并按列记忆、一键重置，Ctrl+K 命令面板可搜材料 / 跳视图 / 执行常用动作；数据存 localStorage，与桌面库各自独立。文件室依赖本机目录与 Shell 缩略图，仅桌面版提供 |
| AI 助手（网页版） | 收在侧栏「更多功能」下。双通道：浏览器 WebGPU 本地跑 Qwen2.5 0.5B / 1.5B 或 DeepSeek R1 蒸馏 7B，对话不出设备；或走 OpenAI 兼容 API（默认 DeepSeek），Key 只存页面内存。可带入台账、名单、任务上下文，提供拆任务、列缺项 / 催交、核对清单、情况说明、评优示例五组快捷指令；只给建议，不改台账、不发消息、不自动归档 |
| 错误与恢复 | 网页端存储失败常驻条、损坏缓存不覆盖、备份结构与条数校验、目录权限错误态、AI 失败脱敏分类；桌面端四段错误对话框、归档失败不再当成功、损坏数据库隔离说明、崩溃日志可导出。错误只说发生了什么 / 影响范围 / 下一步 / 兜底 |
| 文件夹收集 | 选定本机文件夹手动扫描，比对台账列出未登记文件，勾选批量入账并自动编号，登记文件名与路径，不移动原文件 |
| 提交材料 | 四类内置模板（主题班会记录 / 宿舍走访记录 / 班级承诺书 / 违纪约谈记录）加自定义材料入口；选模板带出专属栏目并按模板前缀编号；名称 / 类别必填，个人材料校验姓名学号，一条材料可挂多个附件 |
| 审核流转 | 归档、驳回二次确认，可填写备注 / 原因并留存展示；归档 / 驳回入口按岗位权限点显隐；未选中时操作按钮禁用 |
| 名单核对 | 学号—姓名名单存本机，按「待审核 / 已归档」判已交，只有已驳回的列「需补交」，另给未交与游离材料；完成矩阵可按学生与类别登记免交 / 延期、生成催交话术、登记同学回执，同一学生 24 小时内不重复催交 |
| 服务留痕 | 近 7 天催交、近 7 天回执、有效免交、有效延期四张卡；可按关键词与类型筛选，查看完整话术 / 备注并复制，导出 UTF-8-SIG CSV |
| 届别交接 | 设置中心一键导出交接包 ZIP（数据备份、交接说明、manifest、归档索引与设置参照），导入前显示摘要与覆盖预览；包内不含原始材料文件 |
| 任务跟踪 | 待办事项台账，关联类别、截止日期、应交范围；自动标记临期（≤2 天）/逾期，支持完成、编辑、删除 |
| 表格导入导出 | 台账当前视图导出 CSV（带 BOM）；CSV 批量导入，按表头映射、去重并跳过非法行 |
| 操作日志 | 时间 / 操作人 / 角色 / 动作 / 对象 / 来源自动留痕，可按关键词、动作与操作人筛选；支持导出证据包 |
| 设置中心 | 独立弹窗，外观（明暗 / 十套强调色 / 自定义色 / 表格密度）、界面（申请人学号、侧栏收束、默认视图）、归档（根目录与复制策略）、数据（备份恢复）、关于 |
| 定点归档 | 提交只登记；审核通过后按「类别 / 学号-姓名 / 编号_材料名」复制到归档根目录，根目录维护 `_归档索引.csv`；批量归位只处理已归档材料，同名不覆盖 |
| 备份恢复 | 材料、日志、名单、任务、模板字段与流转事件导出 JSON；导入前先预览数量与风险，确认后才覆盖，失败回滚 |
| 健壮性 | 字段兜底、脏数据跳过、通配符转义、异常落盘、坏库隔离重建 |

### 规划中（见 `docs/` 蓝图，默认不启用）

- 附件真实落盘：桌面端已支持「按类别 / 学号-姓名」复制到归档根目录并维护索引，网页端受静态浏览器边界限制仍只记录文件名。
- 可选本地能力：文件夹后台持续监听、本地批量导入、定时备份。
- 外部对接（默认关闭、用户主动启用）：平台 API、网页链接识别、桌面端 AI 辅助、消息通知。
- 远期：多人协作、手机端、学期归档包。

## 四、快速开始

### 下载现成程序（Windows）

前往 [Releases 页面](https://github.com/MedianiGray/class-console/releases/tag/v0.22.0)
下载附件 `class-console-v0.22.0.exe`，双击即可独立运行，无需安装 Python；数据保存在本机，离线可用。

### 浏览器本地缓存版

`web/index.html` 是单文件网页版，覆盖看板、台账、提交、审核、日志、备份恢复与 AI 助手；
数据保存在浏览器 localStorage 缓存，离线可用、无需后端。AI 助手可选本地 WebGPU 模型（首次下载后缓存在浏览器）
或 OpenAI 兼容 API（Key 只存当前页面内存）。直接用浏览器打开该文件即可；
已部署到 GitHub Pages，公网预览：<https://medianigray.github.io/class-console/>。
注意：浏览器缓存与桌面版 SQLite 数据各自独立，互不同步；文件室仅桌面版提供。AI 助手的加载、API 配置与排障见 [`docs/AI助手使用说明.md`](docs/AI助手使用说明.md)。

### 从源码运行（调试）

1. 安装 Python 3（安装时勾选 tcl/tk，Tkinter 随标准库自带）。
2. 在仓库根目录执行：

```bash
python main.py
```

### 打包 Windows exe

详见 `release/发布说明.md`。在 Windows 上：

```bat
py -3.14 -m pip install "pyinstaller>=6.0"
py -3.14 -m PyInstaller --noconfirm --onefile --windowed --name "班级操作台" main.py
```

产物在 `dist\班级操作台.exe`。打包必须在 Windows 上进行。

### 回归自检

```bash
# 数据层自检（临时库，不读写本机真实数据）
py -3.14 tests/selftest.py

# 界面冒烟回归（需要图形界面环境）
py -3.14 tests/gui_smoke.py
```

全部通过会打印 `SELFTEST OK` / `GUI SMOKE OK`。

## 五、网页原型说明

`prototypes/` 目录存放早期方案对比阶段的**静态 UI 概念稿**，可直接用浏览器打开查看界面设想，
但它们不是可运行的网页应用，不连接数据库、不执行业务流程。当前唯一可运行的版本是本仓库的桌面程序；
网页端 / 多端形态属于远期规划，见 `docs/工作台蓝图.md`。

## 六、数据与隐私

- 本机数据目录（Windows）：`%APPDATA%\ClassConsole\`
  - `console.db`：材料与日志数据库
  - `crash.log`：未捕获异常错误日志
  - `console.corrupt-*.db`：旧库损坏时隔离保留的文件
- 程序不主动联网；外部对接与 AI 能力默认关闭，启用前会明示数据流向。
- 学号、姓名等个人信息最小化收集；敏感材料保留不出本机的选项。

## 七、架构与扩展接缝

界面只调用仓库层方法，不直接触碰 SQL。仓库方法契约固定如下，将来新增 `RemoteRepository`
实现同一组方法后，由 `DATA_BACKEND` 切换，界面与业务流程无需重写：

```
list_docs / add_doc / archive_doc / reject_doc
list_logs / add_log / stats / backup / restore
list_roster / set_exemption / add_followup / add_receipt / service_feed
```

通用对接采用适配器模式：文件夹、文件导入、平台 API、网页链接、AI 各为一个可插拔连接器，
地址、凭据、字段映射走配置，不绑定单一平台。详见 `docs/可选能力与通用对接蓝图.md`。

## 八、路线图

1. **阶段一 · 本地打磨**：名单与缺交核对、CSV 导入导出、审核备注、任务跟踪、免交 / 延期与催交回执、服务留痕已落地；下一步补文件室与首次引导，附件真实落盘待静态边界放开后再做。
2. **阶段二 · 平台接入**：选学校在用平台先只读同步试点，确认字段映射后再开放写入；保留切回纯本地的开关。
3. **阶段三 · AI 辅助**：从分类建议切入，AI 只出建议，关键动作人工确认。
4. **阶段四 · 远期**：多人实时协作、手机端、学期归档包、审计导出。

## 九、当前边界（如实说明）

- 纯离线单机，不保证多人实时一致；多人协作需后续远程方案。
- 附件当前只记录文件名与本机路径，文件本身未落盘；换电脑后历史附件打不开，路径指向的原文件若被移动 / 删除也无法找回。
- 岗位为本地视角切换：经办人 / 审核者 / 汇总者 / 申请人按权限点裁剪界面，未接账号密码登录与服务端强制权限，也无记录级数据范围隔离，不能据此认为已防越权。
- 备份为 JSON；台账另支持 CSV 导入导出；附件本身未落盘，仅记录文件名。
- 自检覆盖代码路径与常见边界，不等于所有环境、所有数据组合零缺陷；尚未在老师本人电脑与大批量数据下实测。
