# 班级材料操作台 · Class Console

> 面向班级学委 / 辅导员的**离线优先**材料工作台：把材料从提交、审核、归档到留痕的流程收拢在一个本地程序里闭环。
>
> 当前版本：**v0.2.2（本地打磨版）** ｜ 运行环境：Python 3 + Tkinter（标准库，零三方运行依赖）｜ 协议：MIT（占位，可更换）

## 一、项目简介

本项目为班级材料收集与归档场景设计，区别于只做链接跳转的导航页：它管理"材料进来 → 状态流转 → 归档留痕"的完整业务过程。

- **交付形态**：Windows 原生桌面程序（Tkinter 窗口），双击 exe 独立运行；不起本地服务、不依赖浏览器、不需要命令行窗口。
- **数据归属**：材料与操作日志保存在本机 SQLite，断网可用；联网与 AI 能力只预留接口，默认不启用。
- **设计原则**：离线优先、先本地后云端、可回退可迁移、隐私最小化、关键动作人工确认。

## 二、功能特性

### 已实现（本地闭环）

| 模块 | 能力 |
|---|---|
| 工作台看板 | 总数 / 待审核 / 已归档 / 已驳回统计卡片、类别分布、待审核置顶、近期动态 |
| 材料台账 | 按材料名 / 姓名 / 学号搜索，类别与状态筛选，详情弹窗，单条材料留痕时间线 |
| 提交材料 | 名称 / 姓名 / 学号 / 类别必填校验，学号格式校验，重复提交确认，附件名记录 |
| 审核流转 | 归档、驳回二次确认；同学视角隐藏审核按钮；未选中时操作按钮禁用 |
| 操作日志 | 时间 / 操作人 / 角色 / 动作 / 对象 / 来源自动留痕，可追溯 |
| 备份恢复 | 材料与日志导出 JSON，导入做结构校验、二次确认、失败回滚 |
| 健壮性 | 字段兜底、脏数据跳过、通配符转义、异常落盘、坏库隔离重建 |

### 规划中（见 `docs/` 蓝图，默认不启用）

- 人员名单与缺交核对、材料任务与截止跟踪、附件真实落盘、Excel/CSV 导入导出、审核备注。
- 可选本地能力：文件夹扫描 / 监听、本地批量导入、定时备份。
- 外部对接（默认关闭、用户主动启用）：平台 API、网页链接识别、AI 辅助、消息通知。
- 远期：多人协作、手机端、学期归档包、审计导出。

## 四、快速开始

### 下载现成程序（Windows）

前往 [Releases 页面](https://github.com/MedianiGray/class-console/releases/tag/v0.2.2)
下载附件 `class-console-v0.2.2.exe`，双击即可独立运行，无需安装 Python；数据保存在本机，离线可用。

### 浏览器本地缓存版

`web/index.html` 是单文件网页版，功能与桌面版对齐（看板、台账、提交、审核、日志、备份恢复），
数据保存在浏览器 localStorage 缓存，离线可用、无需后端。直接用浏览器打开该文件即可；
已部署到 GitHub Pages，公网预览：<https://medianigray.github.io/class-console/>。
注意：浏览器缓存与桌面版 SQLite 数据各自独立，互不同步。

### 从源码运行（调试）

1. 安装 Python 3（安装时勾选 tcl/tk，Tkinter 随标准库自带）。
2. 在仓库根目录执行：

```bash
python main.py
```

### 打包 Windows exe

详见 `release/发布说明.md`。在 Windows 上：

```bat
py -3.14 -m pip install "pyinstaller>=6.0"
py -3.14 -m PyInstaller --noconfirm --onefile --windowed --name "班级操作台" main.py
```

产物在 `dist\班级操作台.exe`。打包必须在 Windows 上进行。

### 回归自检

```bash
# 数据层自检（临时库，不读写本机真实数据）
py -3.14 tests/selftest.py

# 界面冒烟回归（需要图形界面环境）
py -3.14 tests/gui_smoke.py
```

全部通过会打印 `SELFTEST OK` / `GUI SMOKE OK`。

## 五、网页原型说明

`prototypes/` 目录存放早期方案对比阶段的**静态 UI 概念稿**，可直接用浏览器打开查看界面设想，
但它们不是可运行的网页应用，不连接数据库、不执行业务流程。当前唯一可运行的版本是本仓库的桌面程序；
网页端 / 多端形态属于远期规划，见 `docs/工作台蓝图.md`。

## 六、数据与隐私

- 本机数据目录（Windows）：`%APPDATA%\ClassConsole\`
  - `console.db`：材料与日志数据库
  - `crash.log`：未捕获异常错误日志
  - `console.corrupt-*.db`：旧库损坏时隔离保留的文件
- 程序不主动联网；外部对接与 AI 能力默认关闭，启用前会明示数据流向。
- 学号、姓名等个人信息最小化收集；敏感材料保留不出本机的选项。

## 七、架构与扩展接缝

界面只调用仓库层方法，不直接触碰 SQL。仓库方法契约固定如下，将来新增 `RemoteRepository`
实现同一组方法后，由 `DATA_BACKEND` 切换，界面与业务流程无需重写：

```
list_docs / add_doc / archive_doc / reject_doc
list_logs / add_log / stats / backup / restore
```

通用对接采用适配器模式：文件夹、文件导入、平台 API、网页链接、AI 各为一个可插拔连接器，
地址、凭据、字段映射走配置，不绑定单一平台。详见 `docs/可选能力与通用对接蓝图.md`。

## 八、路线图

1. **阶段一 · 本地打磨**：名单与缺交核对、附件落盘、导入导出、审核备注、任务跟踪。
2. **阶段二 · 平台接入**：选学校在用平台先只读同步试点，确认字段映射后再开放写入；保留切回纯本地的开关。
3. **阶段三 · AI 辅助**：从分类建议切入，AI 只出建议，关键动作人工确认。
4. **阶段四 · 远期**：多人实时协作、手机端、学期归档包、审计导出。

## 九、当前边界（如实说明）

- 纯离线单机，不保证多人实时一致；多人协作需后续远程方案。
- 附件当前只记录文件名，文件本身未落盘，换电脑后历史附件打不开。
- 角色为本地视角切换，未接账号密码登录与分级权限，不能据此认为已防越权。
- 仅支持 JSON 备份，尚无 Excel/CSV 导入导出；无审核备注、任务截止跟踪。
- 自检覆盖代码路径与常见边界，不等于所有环境、所有数据组合零缺陷；尚未在老师本人电脑与大批量数据下实测。
