# unkernel 本地引擎验证台

这是技术验证，不是正式工作台。正式版 `web/index.html`、桌面 Tk 程序与数据层一行未改。

## 结论先说

unkernel 是真 Linux 内核编译成 WebAssembly，不是“更快的网页框架”。它适合被放进“更多功能”，按需启动，接管 PDF、音视频、批量脚本这类重活；不适合把材料台账、提交、审核、名单全部搬进 Linux。

原因：

- 内核 WASM 本体 11.26 MB，主工作台首屏不该先付这笔下载与编译成本。
- 客户机看不到本机文件，必须显式挂载；现有桌面文件夹扫描、缩略图、拖入登记不能直接沿用。
- 需要 JSPI。Edge 158 可用，Node 22 不可用；旧浏览器必须退回现有网页模式。
- 基础 busybox 能跑，Python / PDF / 音视频需要发行版镜像与包管理，当前尚未验证。

## 本机实测

测试时间：2026-11-25。环境：Windows 10 10.0.19045 / i5-8250U / 8GB / Edge 158 Headless。

| 项 | 结果 |
| --- | --- |
| JSPI / Memory64 | 通过 |
| `createKernel({ memoryMiB: 256 })` | 257 / 376 / 397 / 413 / 472 / 545 / 572 / 579 / 681 ms（本地回环，多次冷启动/热缓存，含 WASM 编译） |
| 内核 | Linux 7.3.4+，aarch64 |
| `free` | 247,308 kB total（256 MiB 配置） |
| 内核 WASM | 11,259,928 bytes |
| Node 22 CLI | 不支持 JSPI，`createKernel` 直接报 `BootError` |
| Alpine 镜像 | 当前网络无法直连 GitHub Release，未拿到；发行版与 Python 未验证 |

`257 ms` 是最近一次页面内到内核就绪的计时；服务在 `127.0.0.1`，属本地回环 + 热缓存，**不含公网首次下载 11.26 MB**，也不含整页首屏。多次运行在 257–681 ms 间波动，冷启动样本约 545–579 ms，最慢一次出现在 390px 窄屏无头窗口。

## 运行

```powershell
cd lab/unkernel
npm install
npm start
```

打开 `http://127.0.0.1:8780/`，点“启动内核”。需要 Chrome / Edge 137+；没有 JSPI 会显示失败原因。

不启动内核时，页面只加载约 1 MB 的 SDK；点启动后才拉 11.26 MB 的 `unkernel.wasm`。

## 文件

- `unkernel-本地引擎验证台.html`：验证页，真实启动内核、真实 shell、启动/停止/内存与统计。
- `serve.mjs`：本地静态服务，给 `.wasm` 正确 MIME，不依赖第三方包。
- `smoke_cdp.mjs`：用本机 Edge 无头启动，点按钮、跑命令、截图；用于复现。
- `package.json` / `package-lock.json`：固定 `unkernel@0.2.0-261124-75694e2`。

## 接入正式版的门槛

1. **入口**：只在“更多功能 → 本地处理器”出现；不进首屏、不进主导航。
2. **能力**：先接一个真实重活（例如 PDF 拆页或音视频转码），跑通一次再谈扩展。
3. **文件**：用 `MemoryFs` 或宿主目录挂载，明确“哪些文件进了沙盒”；不做自动全盘扫描。
4. **数据**：客户机磁盘用 IndexedDB 持久化，另提供导出；不把唯一副本押在浏览器存储上。
5. **降级**：JSPI 不可用或加载失败时，保留现有网页版，不阻断材料主流程。
6. **许可**：内核 GPL-2.0，SDK MIT；分发时要保留相应许可与源码获取方式。

## 不做什么

- 不做“每个标签页一台 Linux 电脑”的工作台首页。
- 不把材料主流程改写成 Python 服务再套一层终端。
- 不为演示塞假终端、假文件系统、假统计。
