实验 01 · 真实 Linux 内核，不是终端模拟

把内核接在“更多”里，
不把整台工作台搬进去。

unkernel 把 Linux 内核直接编译成 WebAssembly，用户态程序仍走 CPU 模拟。它适合做浏览器里的本地重活引擎，不适合替换材料主流程。先验证启动、终端与边界，再谈接入。

--ms

到内核就绪的实测耗时；本地回环热缓存，含 WASM 编译，不含整页首屏。

接入判断

11.26 MBWASM 单文件，未含 Alpine / Debian 镜像。
256 MiB本次实测配置；官方默认会更高。
按需主工作台照常先开；重活才启动内核。

三个闸门

  1. 浏览器能力Edge 158 通过 JSPI；Node 22 不支持，不能当命令行运行。
  2. 发行版与工具基础 busybox 已跑通；Python / PDF / 音视频需 Distro 镜像，尚未验证。
  3. 数据与文件客户机磁盘可持久化；本机文件必须显式挂载，不能自动扫描。
内核没有启动

结论：把它放在“更多 → 本地处理器”，不要放进首屏。旧浏览器不启动内核，保留现有材料流程。

未启动—
本地验证台，不连接服务器。点“启动内核”后才会加载 11.26 MB WASM。
可用命令：uname -a / cat /proc/version / free / df -h / ls / / ps / help
当前只启动 busybox 基础系统；没有 apk、没有网络、没有 Python。

如果接入正式版

先做加法，不先做拆迁

01

先做一个“本地处理器”入口

放在“更多功能”里，只在用户点开时加载内核。主工作台首屏、台账、名单、提交都不受 11 MB 影响。

02

只接现在桌面才能做的重活

PDF 拆页、音视频转码、批量改名、脚本校验。材料增删改查仍走现有数据层，不经过 Linux。

03

旧浏览器保留退路

没有 JSPI 就显示“当前浏览器不支持本地内核”，继续用现有网页版；不把整台工作台押在一个新特性上。
